외부 검수(2026-10-12)에서 연동 기사 "테스트2"의 연동이 저절로 풀려 있었다. 급한 순서 ①. 근거: `docs/roadmap.md` 37번.
보리 결정(2026-10-13): 원인은 확정 못 했으므로(차량을 지웠는지 기억 안 남) **같은 일이 생기지 않게 막는 쪽**으로.

### 쉬운 요약
- **무엇을:** 기사가 연동 중인 차량을 차주가 지우려 하면, 지우지 않고 "기사 관리에서 연동을 먼저 해제해 주세요"라고 안내한다.
- **왜:** 지금은 그런 차량을 지우면 연동 기록이 아무 흔적 없이 같이 사라진다. 기사 계정은 갑자기 일반 계정이 되고, 차주 "기사 관리"에도 이전 기록이 안 남는다. 검수 증상과 같다.
- **달라지는 점:** 연동 해제는 정해진 절차(해제 요청 → 기사 동의 또는 3일 뒤 자동 해제, 7-C)로만 일어난다.

### 현재 상태 (서버·코드 확인, 2026-10-13 읽기 전용 조회)
- 서버 `driver_links`: "테스트"(7ba50d27…)↔"테스트2"(f58321f9…) 기록은 10/12 18:55(한국)에 새로 만든 1건뿐이다. 표 전체에 "해제됨"(`disconnected`) 기록은 0건이므로 자동 해제(7-C-1)는 원인이 아니다(자동 해제는 지우지 않고 `disconnected`로 바꿈, `0011_driver_unlink_consent.sql:21-24`).
- 연동 중 기록이 지워지는 길: ① 연동 기록 직접 삭제 — 서버 정책이 `linked`면 막음(`차주만 초대 삭제`: `status IS DISTINCT FROM 'linked'`). ② **차량 삭제 → 연동 기록 같이 삭제**(`driver_links_vehicle_id_fkey … ON DELETE CASCADE`). ③ 계정 삭제 → 같이 삭제(지금 두 계정 모두 살아 있어 해당 없음, 연동 중 탈퇴는 0009로 막힘).
- 앱의 차량 삭제(`lib/vehicleDeletion.js:28-80` `requestVehicleDeletion`)는 연동 기사가 있는지 보지 않고 서버 차량 줄을 지운다(`directMutations.js:33`). 서버 `vehicles` 표에도 막는 트리거가 없다(`pg_trigger` 조회 0건).
- 앱은 기사 목록을 이미 들고 있다. 기사 기록에 `status`·`vehicleNumber`가 있고(`outboxTypes.js:14`), 차량 화면도 이 둘로 연동 기사를 찾는다(`CarListPage.jsx:67`).
- 서버 요청 기록은 남아 있지 않다(로그 5일 조회 0건). 그래서 실제로 차량 삭제가 있었는지는 증명 못 함.

### 목표 상태 (기대 동작)
1. 차주가 차량을 지울 때, 그 차량 번호에 `status === 'linked'`인 기사가 있으면 지우지 않는다. 서버 호출 0회, 화면·저장 변화도 없다.
2. 이때 안내 "기사가 연동된 차량은 삭제할 수 없습니다. 기사 관리에서 연동을 먼저 해제해 주세요."가 뜨고, 삭제 확인 창은 열린 채 남는다(지금의 다른 거절과 같은 방식, `vehicleDeletion.js:30`).
3. 연동 해제 요청 중(아직 `linked`)인 차량도 1·2와 같다.
4. 초대만 하고 아직 연동 전(`pending`)이거나, 해제가 끝난(`disconnected`) 차량은 지금처럼 지워진다.
5. 연동 기사가 없는 차량, 비회원(로컬 전용) 차량 삭제는 지금과 똑같다.

### 사용자 확인 방법 (배포본, 차주 "테스트" 로그인)
1. 차량 관리에서 테스트2가 연동된 서브 차량의 [삭제] → [삭제 확인]을 누른다. "기사가 연동된 차량은 삭제할 수 없습니다…" 안내가 뜨고 차량이 그대로 있으면 성공.
2. 테스트2로 로그인해 연동이 그대로인지 본다(초대 코드 입력 화면이 안 뜨면 성공).
3. (선택) 연동 기사 없는 서브 차량을 하나 만들어 지우면 지금처럼 지워진다.

### 확인할 점 (보리 답 필요)
1. **서버에서도 막을까요?** 앱의 검사는 "이 기기에 보이는 기사 목록" 기준이에요. 다른 기기에서 막 연동된 직후처럼 목록이 늦으면 못 막을 수 있어요. 서버에 "연동 중인 차량은 삭제 거절" 규칙을 더하면 확실해요. 이건 DB 변경이라 §9 절차(조회 쿼리 → 보리가 SQL 실행)를 거치고, **다음 슬라이스(37-B)로 따로** 하는 걸 추천해요.
