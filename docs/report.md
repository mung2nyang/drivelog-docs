## 로드맵 24-H-1 운비서 서버 — 미수금 문자 말 알아듣기 `[x]`

보리 지시(2026-10-23, 24-G-2 `[x]` 뒤): "24-H 착수지시서 작성해".
- 로드맵 24-H: 미수금 문자 + 운비서 되묻기. 문자 앱이 연락처·문구가 채워진 채 열리고, [보내기]는 사람이 누른다.
- 24-C·F·G처럼 **둘로 나눔(AI 판단)**:
  - **이번 H-1**: 서버가 "○○에 미수금 문자 보내줘, 문구 1번으로" 말을 새 종류로 나눈다.
  - **다음 H-2**: 앱의 되묻기 버튼과 문자 앱 열기.
- 되묻기는 앱 버튼과 앱 문장만으로 만들고, AI와 여러 번 주고받는 대화는 하지 않는다(로드맵 그대로).

### 확인할 점 (하나) — 언제 "문자"로 알아들을지 — **가로 확정** `[확인: 2026-10-23 보리 — "문자 알아듣기는 가(말에 '문자'가 있을 때만)로"]`
- **권함 가**: 말에 "문자"가 있을 때만 문자 종류로 한다. "한진 미수금 얼마야"는 지금처럼 미수금 질문이다. 24-F-1 "고정"과 같은 방식이다.
- 나: "미수금 보내줘", "독촉해줘"처럼 "문자"가 없어도 AI가 판단한다. 질문과 헷갈릴 수 있다.

### 쉬운 요약
- "한진에 미수금 문자 보내줘, 문구 1번으로", "씨제이 7월분 미수금 문자", "롯데에 입금 요청 문자" 같은 말을 서버가 알아듣는다. 거래처, 어느 달(또는 전체), 몇 번 문구인지로 나눈다.
- 이번엔 서버만 바꾼다. 앱 화면은 다음 H-2에서 바뀐다.

### 현재 상태 (코드 확인)
- 서버 `unbiseo-parse`가 아는 종류는 call·expense·question·fixed·client·unknown이다(`index.ts:105-135`, `grok.ts` INSTRUCTION). 문자 말은 미수금 질문(question unpaid)이나 unknown으로 간다.
- 달은 이미 함수가 "달 표"(`grok.ts` `monthTable`)를 만들어 AI가 고르게 한다(질문 기간에 씀).
- 앱의 문자 문구 3개(`data/sync/messageTemplates.ts`): 1 미수금 안내 · 2 입금 요청 · 3 운행 완료.
  - 이름은 `MessageTemplateSheet.jsx` `TEMPLATE_TITLES`에 있다.
  - 문구는 이 휴대폰에 저장된 바꾼 문구를 쓰고, 없으면 기본 문구다.
- 앱 미수금 묶음은 거래처 + 일한 달 기준이다(`domain/receivables.ts` `groupByClientMonth`). 남은 금액과 건수가 있다.

### 목표 상태 (기대 동작)
1. 새 종류 `kind: 'sms'`, 칸 `sms: { client, month, all, template }`.
   - `client`: 거래처 목록 이름으로 맞추고(운행 client와 같은 규칙), 없으면 들은 그대로, 말 안 했으면 `''`.
   - `month`: "7월분", "지난달" → 달 표의 `YYYY-MM`. 앞으로 올 달이거나 모양이 틀리면 `''`.
   - `all`: "전체", "남은 거 다", "전부"면 `true`, 아니면 `false`. 달과 전체를 같이 말하면 달이 우선이다.
   - `template`: "1번", "문구 1번", "첫 번째" → 1. "미수금 안내" → 1, "입금 요청" → 2, "운행 완료" → 3. 그 밖은 `null`.
2. 문자 종류는 말에 "문자"가 있을 때만 된다(확인할 점 가). "한진 미수금 얼마 남았어"는 지금처럼 question unpaid.
3. 다른 종류(운행·지출·질문·고정·거래처·잡담)는 지금과 같다(기존 시험 문장 전부).
4. 저장, 금액 계산, 문자 보내기는 하지 않는다. 함수 기록에 문장과 답 내용을 남기지 않는다(지금 그대로).
