### 수정 착수지시서 (40-B-2) `[x]` 승인·반영
- **무엇이 실패했나:** `src/components/revenue/OwnerMonthlyCards.driverSelf.test.js`의 `:72` "매출제: 이번 달 정산액·유가보조금 숨김·합계는 운송료−수수료", `:93` "월급제: 이번 달 월급 라벨". 둘 다 화면을 그리다 "`insurance`가 없음" 오류로 멈춤.
- **왜:** 이 테스트는 매출 결과를 손으로 만든 견본(`sampleDetail()`, `:41-69`)으로 화면을 그린다. 견본에 이번에 새로 생긴 `income.insurance` 칸이 없다. 실제 앱에서는 계산 함수가 항상 이 칸을 채우니 문제가 없다(단위 테스트로 확인). 견본만 예전 모양이다. 착수지시서 조사 때 화면 테스트의 견본까지는 보지 않았다.
- **고칠 것:** 견본의 `income`에 `insurance: { total: 0, items: [] }` 한 줄을 더한다. 0원이라 화면에 산재 줄이 안 보이고, 두 테스트의 다른 단언은 그대로 통과해야 한다. 앱 코드는 바꾸지 않는다(화면에 "칸이 없을 때 대비" 코드를 넣지 않음 — 계산 함수가 항상 채우므로).

### 수정 착수지시서 (40-B-1) `[x]` 승인·반영
- **무엇이 실패했나:** `src/domain/driverSelfRevenue.test.js`의 3개 — `:43` "(b) {main: 트립} 입력 직후와 동일…", `:111` "차주 몫이 settlement 라인에 안 들어감", `:120` "지출이 있어도 netProfit은 정산액 유지(Q1)". 셋 다 연동 기사 본인 매출의 **수입 합계**가 425,000원이어야 한다고 보는데 422,000원이 나옴.
- **왜:** 이 테스트들은 공용 시험 데이터의 서브차량 운행(산재보험료 3,000원)을 기사 본인 일지로 쓴다. 이번 결정대로 산재보험료를 빼면 3,000원 줄어드는 게 맞다. 세 테스트 모두 "합계 = 운송료 − 수수료"라는 예전 식을 단언하고 있다. 착수지시서 조사 때 `finance.test.js`·`driverRevenueShareExpense.test.js`만 보고 이 파일의 수입 합계 단언을 빠뜨렸다.
- **고칠 것:** 세 곳의 합계 단언을 새 식으로 바꾼다. "운송료 − 수수료 − 산재보험료", 예: `detail.income.fare.total - detail.income.commission.total - detail.income.insurance.total`. `:49` 메시지도 "운송료−수수료−산재보험료"로. 산재보험료가 3,000원인지도 한 줄 단언한다. 정산액·순이익·운송료 등 나머지 단언은 그대로라 검사가 약해지지 않는다.

### 목표 상태 (기대 동작)
1. 매출(차주·기사·전체 탭)의 콜 상세 산재보험료를 거래처별로 모아 `income.insurance = { total, items }`로 낸다(휴무 날 제외, 다른 값과 같은 규칙).
2. 수입 합계와 순이익에서 산재보험료를 뺀다.
3. "운송 수입" 카드에 "산재보험료 - X원" 줄이 운임 수수료 바로 아래에 생긴다(0원이면 숨김). 눌러 펼치면 거래처별 금액이 보인다.
4. 연동 기사 본인 매출도 같은 줄과 합계 계산을 쓴다.
5. 같은 달·같은 데이터면 매출에서 빠진 산재보험료 = 달력 "산재보험료" 줄 금액(메인 차량 기준).
6. 산재보험료를 안 적은 달은 매출 금액이 지금과 같다.
