## 123-B 운행 입력 창 CSS(`call-detail-form.css` 285줄) 나누기 `[x]`

로드맵 123(`docs/roadmap.md` 605행, ⑥). 보리가 지시서 작성을 지시했다(2026-11-02 "응"). 이번에는 B(`call-detail-form.css`)만 한다. 123-A와 같은 방식으로 옮기기만 한다.

### 쉬운 요약
- 일지의 운행 입력 창 꾸밈 파일이 285줄이다. 머리에 "~250줄까지 허용" 예외 표시가 있지만 그것도 넘었다. 이것을 두 파일로 나눈다.
- 글자 하나 바꾸지 않고 옮기기만 한다. 화면 모양은 그대로다.
- 이번에는 원래 순서 그대로 위아래 두 토막으로 자른다. 그래서 완성된 앱의 꾸밈 묶음이 바꾸기 전과 글자까지 같아야 한다.

### 현재 상태 (코드 확인)
- `src/features/day-log/ui/call-detail-form.css`는 285줄, 규칙 덩이 42개다. `CallDetailForm.jsx` 16행 한 곳만 불러온다(`src` 전체 검색).
- 123-A와 다른 점: 이 파일에는 운행 입력 창 밖까지 닿는 규칙이 섞여 있다(클래스마다 `src` 전체 검색).
  - `.work-log-page .app-temporal-*`(171~196행): 일지 화면 안의 모든 날짜·시간 칸.
  - `.work-log-page input[type='number']`(199~207행): 일지 화면 안의 모든 숫자 칸.
  - `.work-log-page .fixed-route-input-row > label`(70행): 고정 운행 칸(`FixedCountSection.jsx`, `PalletSection.jsx`).
  - 범위 없는 `.input-with-suffix`·`.suffix`(228~258행): 경비 입력(`ExpenseFormModal.jsx`), 고정 운행·파렛트 칸, 계기판 칸(`CallOdometerFields.jsx`)도 쓴다. 경비 입력과 고정 운행은 자기 CSS(`expense-form.css` 47~57행, `fixed-route.css` 28~38행)에서 더 강한 선택자로 덧씌운다.
  - 범위 없는 `.dark-pill-btn`(267~284행), `.call-two-column-panel`, `.call-inline-field`(209~226행): 운행 입력 창의 조각(`CallDetailPaymentFields.jsx`, `CallOdometerFields.jsx`)만 쓴다.
  - 같은 클래스에 `.work-log-page`가 붙은 규칙과 안 붙은 규칙이 둘 다 있다(`.call-inline-field` 79행과 215행). 그래서 규칙의 앞뒤 순서를 바꾸지 않는 것이 안전하다.
- 이 CSS 파일을 직접 읽는 시험은 없다. `inlineSheetCss.test.js`는 `day-log.css`만 읽는다(10·24행).
- 머리 주석(1~2행)에 옮긴 경위("main-calendar.css에서 옮김")와 §6 예외 표시가 있다.

### 목표 상태 (기대 동작)
1. 두 파일로 나뉘고, 둘 다 200줄 이하다. §6 예외 표시는 필요 없어져서 뺀다.
2. 규칙 내용(선택자, 속성, 값)과 규칙의 앞뒤 순서가 한 글자도 바뀌지 않는다. 바뀌는 것은 파일 위치, 머리 주석, 불러오기 줄뿐이다.
3. 빌드한 앱의 꾸밈 묶음(CSS 파일)이 바꾸기 전과 글자까지 같다. 빌드는 주석을 지우므로 머리 주석 차이도 남지 않는다.
4. 운행 입력 창(새로 열기, 기존 운행 열기)에서 모든 요소의 계산된 스타일이 바꾸기 전과 같다.
5. CI(verify, db-test, deploy)가 초록이다.
