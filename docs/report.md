### 쉬운 요약
- **무엇을:** 콜 상세에서 "부가세 없음(면세)"으로 저장한 운행은 달력·홈 정산·운송비 내역서에서도 부가세를 붙이지 않게 한다.
- **왜:** 지금은 하루 화면·매출만 면세를 빼고, 달력·홈·내역서는 다 붙인다. 그래서 10만원 면세 운행이 있으면 1만원이 더 잡힌다. 회사에 내는 내역서 금액도 틀린다.
- **달라지는 점:** 화면마다 부가세 금액이 같아진다.

### 현재 상태 (코드 확인)
- 달력·홈 정산: `domain/monthSettlement.js:147` `vat = Math.round((fare + palletFare) * 0.1)` — 콜 상세의 `vatExempt`를 안 보고, 한 달 합계에 한 번 반올림한다. 이 함수는 달력(`useMonthSettlement.js:35`)·홈(`HomeMonthCard.jsx`)·운송비 내역서 요약(`lib/reportSummary.js:87`, `:115 vat: settled.vat`)이 같이 쓴다.
- 상세 내역서(콜 상세 목록): `lib/reportDetail.js:106` `vat = Math.round(totalFare * 0.1)` — 같은 문제(면세 안 봄). 화면 `ReportDetailView.jsx:162`. 검수 메모엔 없었지만 같은 원인이라 같이 고친다.
- 맞게 하는 곳(기준): 매출 `financeOwnerDetail.js:76·81·98` — 고정노선 금액은 날마다, 파렛트도 날마다, 콜 상세는 건마다 반올림하고, 콜 상세가 `vatExempt`면 0. 하루 화면 `day-record.js:117`도 콜 상세는 건마다·면세 0. 세금계산서 묶음(`financeTaxInvoiceGroups.js:66·169`)도 면세 0.
- 반올림 차이: 매출은 건별·날짜별 반올림, 달력은 월 합계 한 번 반올림 → 금액에 1원 단위가 있으면 몇 원 다를 수 있다(코드로 확인, 검수 금액은 원 단위가 없어 차이 안 남).
- `docs/sot.md`에 부가세·면세 규칙 항목은 없다(검색 0건).

### 목표 상태 (기대 동작)
1. 달력·홈 정산·운송비 내역서 요약의 부가세 = 매출과 같은 규칙: 고정노선 금액(날마다 반올림) + 파렛트(날마다 반올림) + 콜 상세(건마다 반올림, `vatExempt`면 0).
2. 상세 내역서의 부가세 = 표에 나온 콜 상세만, 건마다 반올림, `vatExempt`면 0.
3. 위 부가세를 더하는 합계(달력·홈 "총액", 내역서 총액)도 같이 맞게 바뀐다(합계 계산식 자체는 안 바꿈, `monthSettlement.js:148`).
4. 면세 운행이 없는 달은 원 단위가 없는 한 지금과 금액이 같다(기존 테스트 `monthSettlement.test.js:243` 15,000원, `report.test.js:221·247·273` 그대로 통과).
5. 검수 재현: 10만원 면세 운행 → 달력·홈 부가세가 하루 화면·매출과 같은 값(142,346원)이 된다.
