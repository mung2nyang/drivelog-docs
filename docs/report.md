## 106 라이브러리 보안 알림 — Dependabot `[x]`

로드맵 106(`docs/roadmap.md` 568행, ③). 보리가 Dependabot을 쓰기로 정했다(2026-11-02 "응 작성해 Dependabot으로"). 착수 때 정할 것(월 1회 손 점검 / Dependabot)은 이것으로 정해졌다.

### 쉬운 요약
- 앱이 빌려 쓰는 라이브러리(supabase·엑셀·PDF 만들기 등)에 보안 문제가 알려지면, GitHub가 알려 주고 고치는 PR(고칠 내용 제안)을 연다.
- 지금은 사람이 기억해서 확인해야 한다. 오늘 확인해 보니 이미 알려진 문제가 12개 있다.
- 끝나면 새 문제가 생길 때마다 GitHub 저장소 Security 탭에 뜨고, 고칠 수 있는 것은 PR이 자동으로 열린다. 앱 동작은 바뀌지 않는다.

### 현재 상태 (코드·설정 확인)
- `react-app/.github/`에는 `workflows/`만 있고 `dependabot.yml`이 없다(`ls .github`).
- 저장소 설정을 확인했다.
  - Dependabot 알림이 꺼져 있다(`gh api repos/mung2nyang/react-app/vulnerability-alerts` → 404).
  - 보안 업데이트 PR이 꺼져 있다(`automated-security-fixes` → `enabled: false`, `security_and_analysis.dependabot_security_updates` → disabled).
  - 비밀값 검사는 켜져 있다.
- 지금 알려진 취약점(`npm audit`, 2026-11-02)은 12개다. 심각 1, 높음 2, 보통 9이다.
  - 배포되는 앱에 들어가는 것: `dompurify`(심각, PDF 만들기가 씀)와 `exceljs` 아래 7개(보통). 엑셀 쪽은 판을 내려야만 고쳐진다고 나온다(`exceljs@3.4.0`, 큰 판 바뀜).
  - 개발 도구에만 있는 것: `vite`(높음, Windows 개발 서버), `undici`(높음) 등.
  - `npm audit fix`로 바로 고쳐지는 것: dompurify, undici, vite, rimraf, zip-stream.
- 오래된 라이브러리(`npm outdated`)는 13개다. 예: supabase-js 2.112.3 → 2.118.0, vite 7.3.6 → 8.3.5.
- CI가 쓰는 GitHub 도구는 6개다(`actions/checkout@v7`, `setup-node@v7`, `upload-pages-artifact@v5`, `configure-pages@v6`, `deploy-pages@v5`, `denoland/setup-deno@v2.0.5`).
- CI는 PR에서도 돈다(`ci.yml` `on: pull_request`). 비밀값을 쓰는 단계는 없다. 배포는 main에서만 한다.
- 서버 함수는 supabase-js를 `npm:@supabase/supabase-js@2.112.3`처럼 코드 안에 판을 적어 쓴다(세 `handler.ts` 2행). Dependabot은 이 적는 법(Deno)을 읽지 못한다.

### 목표 상태 (기대 동작)
1. 저장소 Security 탭에서 Dependabot 알림이 켜져 있다. 지금 있는 취약점이 알림 목록에 뜬다.
2. 보안 업데이트 PR이 켜져 있다. 고칠 수 있는 취약점은 하나로 묶인 PR이 열린다(라이브러리마다 PR이 따로 열리지 않게 한다).
3. 보안과 상관없는 판 올리기 PR(npm)은 열리지 않는다(아래 확인할 점 2).
4. CI가 쓰는 GitHub 도구는 한 달에 한 번, 새 판이 있으면 하나로 묶인 PR이 열린다(확인할 점 2).
5. 저장소 Insights → Dependency graph → Dependabot 화면에서 설정 파일 오류가 없다.
6. 앱 코드와 CI는 그대로다. CI는 초록이다.

### 건드릴 파일
- `react-app/.github/dependabot.yml`(새로 만듦):
  ```yaml
  # 알려진 보안 문제가 있는 라이브러리를 GitHub가 알리고 고치는 PR을 연다.
  version: 2
  updates:
    - package-ecosystem: npm
      directory: /
      schedule:
        interval: monthly
      # 판 올리기 PR은 받지 않고 보안 업데이트만, 한 PR로 묶는다.
      open-pull-requests-limit: 0
      groups:
        security:
          applies-to: security-updates
          patterns: ['*']
    - package-ecosystem: github-actions
      directory: /
      schedule:
        interval: monthly
      groups:
        actions:
          patterns: ['*']
  ```
- 보리가 GitHub 화면에서 할 것(보안 설정이라 AI가 바꾸지 않는다): 저장소 Settings → Advanced Security(또는 Code security)에서 두 가지를 켠다(Enable).
  - Dependabot alerts
  - Dependabot security updates

### 안 건드릴 것
- 지금 있는 취약점 12개 고치기. 라이브러리 판을 바꾸면 앱 동작이 바뀔 수 있어서 따로 한다(확인할 점 3). 이번에는 알림 장치만 만든다.
- `package.json`·`package-lock.json`, 앱 코드(`src/`), `ci.yml`.
- 서버 함수의 `npm:` 판 적기. Dependabot이 읽지 못한다. 앱의 supabase-js를 올릴 때 손으로 같이 맞추고 배포한다.
- 자동 합치기(auto-merge). PR은 사람이 확인한 뒤에만 반영한다.

### 검증
- 코드 커밋 1개를 main에 한다. 작업 가지는 쓰지 않는다. Dependabot은 기본 가지(main)의 설정 파일만 읽어서, 작업 가지로는 시험할 수 없다.
- 보리가 push한 뒤 확인한다.
  - CI가 초록이다(목표 6).
  - 보리가 두 설정을 켜면 AI가 다시 확인한다. `vulnerability-alerts`는 204, `automated-security-fixes`는 `enabled: true`여야 한다(목표 1·2).
  - Dependabot이 연 PR 목록(`gh pr list`)을 본다. npm 보안 PR이 하나로 묶였는지, 판 올리기 PR이 없는지 확인한다(목표 2·3).
  - 로그인해 둔 브라우저 탭에서 Insights → Dependency graph → Dependabot을 열고, 설정 파일 오류가 없는지 본다(목표 5).
  - GitHub 도구 PR(목표 4)은 다음 달 일정에 열리므로, 처음 확인 때는 "설정 오류 없음"까지만 본다.

### 실패 시 처리
- 새 대비 장치는 만들지 않는다.
- 설정 파일 오류가 나거나 PR이 묶이지 않고 따로 열리면, 원인과 수정 계획을 이 파일에 수정 지시서로 써서 다시 확정받는다.
- 열린 PR은 합치지 않고 그대로 둔다.

### 사용자 확인 방법
1. GitHub 저장소 → Settings → Advanced Security에서 Dependabot alerts와 Dependabot security updates를 켠다.
2. Security 탭 → Dependabot을 연다. 알림 목록에 dompurify(Critical) 등이 보이면 성공이다.
3. Pull requests 탭을 연다. Dependabot이 연 보안 PR이 하나(묶음) 보이면 성공이다. 합치지는 않는다.

### 확인할 점
1. Dependabot PR이 열리면 어떻게 처리할지 정해야 한다.
   - 가. AI가 슬라이스로 처리한다. 지시서를 쓰고, 같은 업데이트를 main에 커밋하고, CI와 화면을 확인한다. main에 반영되면 Dependabot이 PR을 스스로 닫는다.
   - 나. AI가 PR을 확인한 뒤 보리가 GitHub에서 [Merge]를 누른다.
   - 가를 권한다. 지금의 "슬라이스당 커밋 2개, push는 보리" 흐름과 화면 확인을 그대로 지킬 수 있다.
   - 정해지면 [x] 때 로드맵 106 줄과 STATUS에 적는다. `AGENTS.md`에 넣을지는 보리가 정한다.
2. 판 올리기 PR을 받을지 정해야 한다.
   - npm은 보안 업데이트만 받는 것을 권한다. 지금 오래된 라이브러리가 13개라 PR이 자주 열리고, 하나하나 확인해야 한다.
   - CI의 GitHub 도구는 한 달에 한 번 묶어 받는 것을 권한다. 도구는 6개뿐이고, 오래된 도구는 GitHub가 끊어 CI가 멈출 수 있다.
3. 지금 있는 취약점 12개 처리. 설정을 켜면 바로 알림과 PR이 뜬다.
   - 106 다음 슬라이스로 로드맵에 새 번호를 올릴지 정해야 한다.
   - dompurify(심각, 앱에 들어감)를 먼저, 엑셀 쪽(판을 내려야 함)은 따로 따지기를 권한다.
