## Capacitor 전환 C-8 — 뒤로가기로 옆 메뉴 먼저 닫기 `[x]`

2026-11-06 보리 요청("으" — C-8 착수지시서 쓸까요에 대한 답). 승인 `[확인: 2026-11-06 보리 — "응 착수지시서 확정,작업진행해"]`. 근거: 로드맵 "Capacitor 전환" C-8과 그 원인 조사(2026-11-06), C-5 진행 기록의 발견. 이번 것은 화면 코드라 앱 파일은 다시 만들지 않아도 됨(앱은 배포된 사이트를 부름). C-8이 끝나면 1.0.3을 한 번에 올림.

### 쉬운 요약
- 옆 메뉴(왼쪽 위 메뉴 버튼)를 연 채 휴대폰 뒤로가기를 누르면, 메뉴가 닫히지 않고 뒤 화면으로 가거나 홈이면 "한 번 더 누르면 종료" 안내가 뜹니다.
- 메뉴를 열면 뒤로가기 한 번은 메뉴만 닫게 합니다. 앱과 크롬(바탕화면 설치 포함) 모두 같게 고칩니다.

### 현재 상태 (코드 확인)
- 메뉴 열림은 화면 안 값뿐(`AppShell.jsx:97` `useState(false)`)이고 화면 기록을 쌓지 않음 → 뒤로가기는 메뉴를 모르고 그 앞 기록으로 감. 크롬 설치 앱도 같은 방식(C-5 진행 기록에서 에뮬레이터로 확인한 증상).
- `AppShell.jsx`는 정확히 200줄(§6 한도). 메뉴 항목을 눌렀을 때 화면 이동 + 닫기는 `SideMenu.jsx`(146줄) 안의 `pick`·`openSubLog`·`openLinkedDriver`가 하고, 메뉴 바깥(어두운 곳)을 누르면 `onClose`(`SideMenu.jsx:44-63`) → `AppShell.jsx`는 안 건드리고 `SideMenu.jsx` 쪽에서 처리할 수 있음.
- 같은 방식의 앞선 예: 일지 입력 칸이 열린 동안 붙잡기 기록을 한 장 쌓아 뒤로가기를 받는 `usePanelBackGuard.js`(`historyMoves.js` `panelGuardOnTop`·`popPanelGuardThen`). 메뉴는 사용자가 눌러서 여는 것이라 웹뷰가 이 기록을 건너뛰지 않음(C-5 수정 2에서 확인한 "누르기 전 기록 건너뛰기"에 안 걸림).

### 목표 상태 (기대 동작)
1. 메뉴를 연 채 뒤로가기 1번 → 메뉴만 닫히고 보던 화면 그대로(홈이면 종료 안내 안 뜸).
2. 메뉴가 닫힌 뒤 뒤로가기는 지금과 같음(홈이면 종료 안내, 다른 화면이면 앞 화면).
3. 메뉴 바깥을 눌러 닫거나 메뉴 항목을 눌러 다른 화면으로 가도 뒤로가기 횟수가 늘지 않음(메뉴 때문에 쌓은 기록은 조용히 빼고 나서 이동).
4. 앱(안드로이드 뒤로가기)·크롬 탭·바탕화면 설치 앱 모두 같음.

### 건드릴 파일
- `react-app/src/app/shell/useSideMenuBackGuard.js`(새 파일, 약 40줄) — 메뉴가 열리면 같은 주소로 붙잡기 기록 1장(`menuGuard` 표시, 지금 기록의 표시는 그대로 이어 붙임), 뒤로가기로 그 기록이 빠지면 메뉴 닫기, 바깥 누르기·항목 누르기로 닫을 때는 그 기록을 조용히 뺀 뒤 다음 일(이동)을 함. 주석: `// 옆 메뉴가 열린 동안 붙잡기 기록을 1장 쌓아, 휴대폰 뒤로가기는 메뉴만 닫는다.`
- `react-app/src/shared/utils/historyMoves.js` — 입력 칸용 `panelGuardOnTop`·`popPanelGuardThen`을 표시 이름(`panelGuard`/`menuGuard`)을 받게 넓힘(기존 부르는 곳은 그대로 동작). 73 → 약 80줄.
- `react-app/src/app/shell/SideMenu.jsx` — 위 훅을 부르고(`if (!open) return null` 앞에서), `pick`·`openSubLog`·`openLinkedDriver`·바깥 누르기를 "기록 빼고 나서 이동·닫기"로.
- 새 시험 `react-app/src/app/shell/useSideMenuBackGuard.test.js` — 열면 기록 1장, 뒤로가기면 닫힘(기록 원래대로), 바깥 누르기면 기록 빠짐, 항목 누르기면 기록 빠진 뒤 이동(기록 수가 메뉴 없을 때와 같음).

### 안 건드릴 것
- `AppShell.jsx` — 200줄이라 손대지 않음(메뉴 열림 값은 그대로 거기 있고, 닫기는 `onClose`로만).
- `useBackToExit.js`·`useAppBackButton.js` — 메뉴 기록이 빠질 때 홈 종료 안내 조건(첫 기록 번호 0)에 안 걸림(`useBackToExit.js` `isExitEdge`는 번호 0일 때만). 시험으로 확인.
- `usePanelBackGuard.js` — 메뉴 기록이 입력 칸 붙잡기 표시를 이어 받으므로, 입력 칸이 열린 채 메뉴를 열어도 입력 칸 쪽이 "뒤로가기 눌림"으로 착각하지 않음. 입력 칸이 열린 채 메뉴 버튼을 누를 수 있는지는 작업 중 확인하고, 문제가 있으면 수정 착수지시서로.
- 앱 파일(`android/`) — 화면 코드만 바뀌어 다시 만들 필요 없음. 단 1.0.3 묶음은 v4 지금 파일 그대로(C-3~C-7) 올리면 됨.
