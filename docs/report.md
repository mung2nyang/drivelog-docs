### 목표 상태 (기대 동작)
1. 서버 함수 `unbiseo-parse`(Supabase Edge Function, Deno). 받는 것: `{ text: 글자(1~300자), today: 'YYYY-MM-DD', clientNames: 거래처 이름 목록(최대 200개, 각 50자) }`. 모양이 틀리면 400.
2. **로그인한 사람만**: 요청 머리의 로그인 표(JWT)로 Supabase에 "누구인지" 물어 사용자가 없으면 401. 함수 설정 "Verify JWT"는 켬(기본값 — 지금 서명 키 ECC도 확인함, 앱의 공개 키 `sb_publishable_…`만 보내면 여기서 막힘). 다만 예전 `anon` 키(HS256, "이전 키"로 아직 유효)도 이 확인을 통과하므로 함수 안에서 사용자 확인을 꼭 함(내장 비밀값 `SUPABASE_URL`·`SUPABASE_ANON_KEY` + 요청의 로그인 표로 `auth.getUser()`). 하루 횟수 제한은 안 함(로드맵 11번, 출시 직전).
3. AI 부르기: Gemini 공식 SDK(`npm:@google/genai` 버전 고정)로 Flash-Lite 모델·짧은 지시문·정해진 칸 모양(JSON 응답 스키마)을 보냄. 생각 기능이 있으면 가장 낮게(값·속도). 키는 함수 비밀값 `GEMINI_API_KEY`에서만 읽음. 이 부분은 `gemini.ts` 한 파일에만(나중에 회사 바꾸기 쉽게).
4. 돌려주는 모양(앱이 믿기 전에 함수가 한 번 더 모양 확인):
   - `{ kind: 'call', call: { date, loadLoc, unloadLoc, fare, client } }` — `date`는 'YYYY-MM-DD'(말에 "어제" 등이 있으면 `today` 기준으로 계산, 없으면 `today`), `fare`는 원 단위 정수 또는 없음(못 알아들음), `client`는 `clientNames` 중 하나와 같으면 그 이름, 아니면 들은 그대로(24-B 창에서 고름).
   - `{ kind: 'expense' }`, `{ kind: 'question' }` — 이번엔 종류만(칸은 24-C·D).
   - `{ kind: 'unknown' }` — 일지·질문과 관계없는 말.
   - AI가 이상한 값을 주면(모양 틀림·멈춤·거절) 502 + 쉬운 문구 "알아듣지 못했습니다. 다시 말해 주세요." AI 회사 장애·키 없음은 503 "잠시 뒤 다시 시도해 주세요." 재시도 없음.
5. **로그에 말한 내용을 남기지 않음**(개인정보) — 실패 종류·시간만.
6. 금액 계산·저장은 안 함. 함수는 나누기만, 저장은 24-B에서 사람이 [저장]을 눌러야.
