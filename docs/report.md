## 로드맵 41-B-1 해제된 예전 계약 받아 두기 (불러오기·보관) `[x]`

2026-11-03 보리 요청("41-b로 진행", A안 설명 뒤 "권함으로 진행해"). 근거: `docs/roadmap.md` 41-B. 41-A(react-app `8aec4ca`, 연동 중 계약만 기간으로)의 뒤. 41-B를 두 조각으로 나눈 것 중 1번(받아 두기)만 한다. 2번 41-B-2(계산·줄 이름)는 따로 지시서.

정한 것 `[확인: 2026-11-03 보리 — "권함으로 진행해"]`:
- A안: 해제 기록은 기사 목록과 다른 칸(`driverHistory`)에 담는다. 새 상태값(AGENTS §7) 허락.
- 그 칸은 휴대폰에 저장하지 않는다(메모리만, 앱 켤 때마다 서버에서 새로 받음).
- 줄 이름 `이전 기사 (시작~끝)`, 계산은 지금 차량 설정 — 41-B-2에서.
- 범위는 매출 화면만. 기사 관리 화면 숫자 맞추기는 41-B 뒤 따로.

### 쉬운 요약
- 앱이 켜질 때 서버에서 받아 오던 "해제된 예전 계약"(차량·시작일·끝난 날)을 버리지 않고 따로 담아 둔다.
- 이번엔 담아 두기만 한다. 매출 화면 숫자는 41-B-2에서 바뀐다.
- 기사 목록·기사 관리 화면·서버(DB)는 그대로.

### 현재 상태 (코드 확인)
- 서버는 해제할 때 계약 기록을 지우지 않고 `status = 'disconnected'`, `assignment_end = 해제한 날`로 바꿔 둔다(`supabase/migrations/0011_driver_unlink_consent.sql:22`, `0012_driver_unlink_copy_records.sql:145`).
- 차주 앱은 이 기록을 이미 받아 온다(`data/sync/driverUnlink.ts:40` — `owner_id`로 전부 조회, 상태로 거르지 않음). 그런데 `data/hydrate/hydrateMerge.ts:54`가 `disconnected`를 버린다.
- 그래서 앱 안 어디에도 예전 계약 기간이 없다. 기사 급여 계산(`domain/driverRevenueShareExpense.ts:14`)은 연동 중 계약 하나만 본다.
- 메모리에만 두는 칸은 이미 같은 모양이 하나 있다: `driverExpenses`(`data/store/app-store.ts:37`, `commitBatch`의 `replaceDriverExpenses`, `data/store/owner-state.ts:114`). 휴대폰 저장 대상(`PersistDomain`) 밖이라 저장 코드를 안 탄다.
- 로그인 계정은 기사 목록·일지 등 업무 자료를 원래 휴대폰에 저장하지 않는다(`data/store/batchWrites.ts:18` `CLOUD_MEMORY_ONLY_DOMAINS`에 `drivers` 포함). 그래서 새 칸을 메모리만으로 둬도 인터넷 없이 켤 때 이 칸만 따로 비는 일은 없다(앞서 대화창에서 말한 단점은 사실이 아니었음 — 다른 업무 자료와 같은 처지).
- 연동 기사 세션(`performHydrate`의 `employedDriver`)은 차주 기록을 받지 않는다(`hydrate.ts:66~81`).

### 목표 상태 (기대 동작)
1. 차주 계정이 앱을 켜면(불러오기 끝) `getState().driverHistory[ownerKey]`에 해제된 계약이 `{ id, vehicleNumber, assignmentStart, assignmentEnd, status: 'disconnected' }` 모양으로 시작일 순서대로 들어간다. 모양은 계산이 이미 받는 `DriverLinkLike`(`domain/financeTypes.ts:38`)와 같다.
2. 차량 번호는 그 기록의 `vehicle_id`로 지금 차량 목록에서 찾는다(번호를 바꿨으면 바뀐 번호). 차량을 못 찾거나 시작일·끝난 날이 비어 있으면 담지 않는다.
3. 기사 목록(`drivers`)은 지금과 똑같다(해제 기록은 여전히 안 들어감).
4. 이 칸은 휴대폰 저장소(localStorage)에 쓰지 않는다. 불러올 때마다 통째로 바꾼다(빈 목록이면 빈 목록으로).
5. 다른 칸과 같은 한 번의 반영(`replaceOwnerState` → `commitBatch` 1회, 알림 1회) 안에서 바뀐다. 불러오는 사이 계정·세션이 바뀌면 다른 칸처럼 반영하지 않는다(기존 `isSessionStillCurrent` 확인 그대로).
6. 연동 기사 세션에서는 빈 목록이다.
7. 화면에 보이는 것은 아무것도 안 바뀐다(아직 읽는 곳 없음).

코드에 넣을 주석(최종 문구):
- `app-store.ts` 칸 옆: `// 해제된 예전 계약(메모리 전용, hydrate replace) — 기사 급여 계산용`
- `hydrateMerge.ts` 새 함수 위: `/** 해제된 계약만 계산용 모양으로. 차량을 못 찾거나 기간이 비면 뺀다. */`
