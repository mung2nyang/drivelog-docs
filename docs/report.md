## 11-D-3 심사용 접근 안내(플레이 콘솔 "앱 액세스 권한") `[x]`

보리 요청(2026-11-03, "작성해"). 근거: 로드맵 11번, `play-store-listing.md` 3항 "앱 액세스 권한 — 안내 문구는 11-D-3에서 확정", 11-D-2(`db31525`) 다음. 이번엔 **11-D-3만**.

### 쉬운 요약
- 구글 심사 담당자가 앱의 모든 기능을 볼 수 있도록 "어떻게 들어가는지"를 콘솔에 적는다.
- 로그인해야만 쓰는 기능(운비서·일상점검표·기사 연동 등)이 있어서, 구글 기준상 **심사 전용 구글 계정**과 영어 안내가 필요하다.
- 앱 코드는 안 바뀐다. 콘솔에 붙여 넣을 영어 안내문과 계정 준비 순서를 문서로 만든다.

### 현재 상태 (코드 확인)
- 첫 화면 단추: "Google 계정으로 로그인하기", "비회원으로 시작하기"(`AuthIntroView.jsx` 52·55줄). 첫 구글 로그인 때 이름·휴대전화 번호 입력 화면이 나온다(`WelcomeProfileView.jsx` 20줄, 번호 10자리 이상).
- 비회원으로 되는 것: 운행 기록·달력·지출·매출·운송비 내역서·세금계산서 자료(기록은 휴대폰에만, sot 620줄).
- 로그인해야 되는 것: 운비서(`HomeAssistantPanel.tsx` 18줄 "로그인하면 쓸 수 있습니다", `UnbiseoDock.tsx` 27줄), 일상점검표(`DocumentIssuePage.jsx` 45줄), 기사 초대·연동(sot 706~707줄), 1:1 문의(sot 733줄), 여러 기기 이어 쓰기·서버 저장(sot 620줄).
- 구글 기준([로그인 정보 요구 사항](https://support.google.com/googleplay/android-developer/answer/15748846?hl=en)): 기능이 로그인으로 막혀 있으면 "Google로 로그인"이라도 계정 정보와 자세한 안내를 줘야 한다. 계정은 언제·어디서나 다시 쓸 수 있어야 하고(비밀번호 만료 금지), 2단계 인증은 건너뛸 수 있어야 하며, 안내는 영어로 쓴다. 실제 사용자 계정은 주면 안 된다.
- drivelog-docs는 공개 저장소 → **비밀번호를 문서에 적으면 안 된다.**

### 목표 상태 (기대 동작)
1. `play-store-listing.md`에 "앱 액세스 권한" 칸을 만든다: 콘솔에서 고를 답("일부 기능 제한"), 콘솔 칸마다 넣을 값(이름·아이디·비밀번호 자리·그 밖의 안내).
2. 영어 안내문(콘솔 "그 밖의 안내" 칸에 붙여 넣기) — 비회원으로 볼 수 있는 기능, 로그인해야 하는 기능과 들어가는 순서, 화면이 한국어라는 점, 단추 이름은 한국어 원문을 같이 적음.
3. 심사 계정 준비 순서(보리가 할 일): 새 구글 계정 만들기 → 2단계 인증 끔 → 앱에서 한 번 로그인해 이름·번호·첫 설정을 끝내 두기(심사자가 첫 화면 입력에서 막히지 않게) → 콘솔에 아이디·비밀번호 직접 입력.
4. 문서에는 계정 **아이디까지만** 적고 비밀번호는 적지 않는다(콘솔에만 입력).
5. 3항 표의 "앱 액세스 권한" 줄을 확정 값으로 고친다.
