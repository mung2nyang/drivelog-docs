1. 앱에서 같은 이름 파일을 덮어쓸 수 있으면 지금처럼 덮어쓴다(파일이 늘지 않음).
2. 덮어쓰기가 실패하면 `이름 (2).확장자`, 그것도 실패하면 `(3)` … 최대 `(5)`까지 차례로 시도해 처음 성공한 이름으로 저장하고, 지금과 같은 위치 안내를 돌려준다.
3. 다 실패하면 맨 처음 실패를 그대로 던진다 → 지금과 같은 실패 알림.
4. 확장자가 없는 이름은 끝에 ` (2)`를 붙인다.
5. 웹은 그대로(링크 내려받기, 브라우저가 이름을 알아서 바꿈).

### 건드릴 파일
- `react-app/src/shared/utils/saveFile.ts` — 번호 붙인 이름 만들기와 차례로 시도하기.
- `react-app/src/shared/utils/saveFile.test.js` — 시험 추가: 첫 쓰기 실패·`(2)` 성공 → 두 번째 경로가 `운행일지/2026년_11월_운송비내역서 (2).pdf`이고 안내를 돌려줌, 다섯 번 다 실패 → 첫 오류를 던지고 쓰기 시도 5번, 확장자 없는 이름.
- 주석 최종 문구: `// 앱을 다시 깔면 예전 앱이 만든 같은 이름 파일은 덮어쓸 수 없어, 번호를 붙여 새로 저장한다.`

### 안 건드릴 것
- 부르는 곳 5곳 — 돌려받는 값(위치 안내)과 실패 때 던지는 것이 그대로라 안 바꿈(위 grep 목록).
- `shareFile.ts` — 캐시 폴더라 해당 없음.
- 지운 예전 파일 정리·권한 요청 — 하지 않음(다른 앱 파일은 지울 수 없고 권한은 스토어 심사 부담).

### 검증
- `npm test`(새 시험), revert-check(고치기 전 코드에서 새 시험 실패 확인), lint·typecheck.
- 에뮬레이터: 앱 지우고 깔기 → 같은 날 백업 저장 → 성공 안내, 문서/운행일지에 `운송내역_백업_2026-11-07 (2).json`. 한 번 더 저장 → 파일이 더 늘지 않음.
