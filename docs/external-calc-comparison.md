# 시중 운송·정산 앱 계산 방식 비교

> 문서 성격: **AI 관찰 (미확인 — 실행 지시 아님)**
> 조사 날짜: 2026-10-21
> 조사 기준: 우리 앱 react-app `f9cd2ec` 기준. 외부 앱은 아래 "조사 방법"대로 읽음.
> 작성 원칙: 외부 앱 코드를 우리 앱에 옮겨 적지 않았고 계산 방식만 비교했다. 우리 앱 코드는 고치지 않았다.
> 이 문서는 버그 판정이나 수정 승인을 뜻하지 않는다. 숫자가 다른 것까지만 확인했고,
> 맞고 틀림은 보리 결정이 필요한 항목으로 따로 적었다.

## 3. 비교로 확인된 것

1. **부가세 끝전 — 우리 앱만 "반올림", 나머지는 "버림" 쪽.**
   화물노트·날라는 버림, 화물기록부는 세액을 안 매기고 공급가만 둔다. 예: 공급가 15,555원이면
   우리 1,556원, 날라·화물노트 1,555원. 세무에서 부가세 끝전은 버림이 일반적이라 알려져 있다.
   관련 코드(부가세를 `Math.round(x * 0.1)`로 계산하는 곳 전부, 6개 파일 — 일부만 바꾸면 화면끼리 1원씩 어긋남):
   - `react-app/src/domain/monthSettlement.js:97,117,123` (달력)
   - `react-app/src/domain/financeOwnerDetail.js:79,87,104` (매출)
   - `react-app/src/domain/day-record.js:117,138` (하루 화면)
   - `react-app/src/domain/financeTaxInvoiceGroups.js:67,78,171` (세금계산서)
   - `react-app/src/features/documents/api/reportDetail.js:105` (운송비 내역서)
   - `react-app/src/features/day-log/ui/CallDetailForm.jsx:61` (입력 창 "부가세 포함" 미리보기)
   **보리 결정(2026-10-21): 버림으로 바꾼다.** → 로드맵 102 `[x]` react-app `db5ea29`(2026-10-22, 건마다 버림).
   규칙은 `docs/sot.md` §4-14, 작업은 `docs/roadmap.md` 102번.

2. **세무 금액 끝전을 10원 단위로 맞추는 곳이 있다.**
   날라는 산재보험료를 10원 단위 버림한다. 우리 앱 3.3%는 정산액 x 3.3%를 한 번에 계산해 1원 미만 버림
   (`driverIncomeDeductions.js` `floorWon` 27~29줄, 원천징수 83줄).

3. **미수금을 공급가(부가세 제외)로 잡는 건 우리 앱만의 방식이 아니다** — 화물기록부도 같다.
   화물노트만 부가세 포함. 즉 앱마다 갈리는 선택지이고 보리 결정 사항.

4. **유가보조금을 매출에 더하는 방향은 우리 앱·화물기록부가 같다**(화물노트만 안 더함).
   우리 앱이 틀린 게 아니라는 근거.

## 4. 산재보험료 — 세무·노무 확인 결과(보리 제공)

세무·노무 설명으로 받은 계산 구조: ① 사업소득에서 ② 경비 명목(화물차주)을 빼고 ③ 월보수액 x 1.8%(화물차주)
④ 사업주·차주 절반씩. 산재 적용 예외는 "개인 화주로부터 직접 의뢰받는 경우"(사업자 화주면 적용).

- **우리 앱 산재 모델은 이 설명과 구조가 같다** — `react-app/src/domain/driverIncomeDeductions.js`:
  월보수액 = 정산액 - 정산액 x 경비율, 산재총액 = 월보수액 x 1.8%, 사업소득자면 기사 50%.
  즉 우리 앱 산재 계산 구조(2절 표 "산재보험료" 줄)는 맞는 것으로 확인. 날라의 "운임 x 0.44% 단일률"은 주선사용 다른 방식.
- **확인 필요한 숫자:**
  - 경비율: 우리 앱 기본값은 30.5% 하나(`DEFAULT_EXPENSE_RATE`). 43.1%(살수차 등)는 차량 창 안내 문구로
    "직접 고쳐 달라"고만 함(`CarDriverIncomeFields.jsx:10`). 세무 설명 예시는 30.3%. 근로복지공단 고시로 확인.
  - 한시적 50% 감경(2023-07부터 1년): 오늘(2026-10) 기준 만료로 보임. 만료면 현행 1.8% 전액이 맞음.
    연장·재시행 여부는 공단 확인. 우리 앱은 자동 감경 없음(요율 칸 수동 조정만 가능).

## 7. 조사 방법 메모(재현용)

- 화물노트: PC 장부 페이지의 `truck-sqlite-parser` JS를 읽고, 같은 스키마의 시험 SQLite를 브라우저에서
  만들어 `parseTruckDatabase`에 넣어 공급가·부가세·미수를 확인했다.
- 화물기록부: APK를 jadx 1.5.6(Microsoft OpenJDK 21)로 Java 되돌림. 계산은 `TaxViewModel`·`VatViewModel`·
  `StatViewModel`의 흐름 코드에 있다. 부가세 역산(1.1 나눔)·유가보조금 매출 가산·수익률 식 확인.
- 날라: 주문 화면 `calculateFee()` — 부가세 = floor(운임 x 0.1), 산재 = floor(운임 x 0.0044 / 10) x 10,
  실지급 = 운임 + 부가세 - 산재. 정산 목록 금액은 서버에서 완성돼 내려옴.
- 설치 파일·되돌린 코드·시험 스크립트는 모두 저장소 밖 임시 폴더에만 두었다(저장소에 남기지 않음).
