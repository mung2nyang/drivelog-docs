### 쉬운 요약
- 기사 차량 산재보험료 계산에 쓰는 기본 숫자가 옛날 것(필요경비율 30.5%, 요율 1.8%)이라, 지금 고시(49.9%, 1.76%)로 바꿉니다.
- 지금은 산재가 실제보다 약 40% 크게 나옵니다(월급 200만원: 실제 기사·차주 각 8,810원, 앱 각 12,510원). 고치면 기사 실수령·차주 지출이 실제와 맞습니다.
- 끝전도 근로복지공단처럼 기사 몫·차주 몫을 따로 계산해 10원 미만을 버립니다.

### 현재 상태 (코드 확인)
- 기본값: `domain/driverIncomeDeductions.ts:9-10` `DEFAULT_EXPENSE_RATE = '30.5'`, `DEFAULT_INSURANCE_RATE = '1.8'`.
- 차량을 저장하면 요율이 늘 글자로 함께 저장된다(`driverIncomeFieldsFromDraft` 35-43줄) — 그래서 기본값만 바꾸면 한 번이라도 저장한 차량은 옛 값 그대로, 저장 안 한 옛 차량만 새 값이 되어 차량마다 갈린다.
- 계산: 월보수액 = 정산액 − 정산액 × 경비율(1원 미만 버림), 총액 = 월보수액 × 요율(1원 미만 버림), 사업소득자는 기사 = 총액 ÷ 2 버림·차주 = 나머지, 근로자는 차주 전액(66-81줄).
- 공단 방식: 사업주·종사자가 각각 월보수액 × 요율 ÷ 2를 계산해 원단위(10원 미만) 절사(공단 안내서 19쪽 예시 6,273,000원 × 0.9% = 56,457 → 56,450원).
- 서버(기사 본인 화면 `get_assigned_vehicle_summary`)는 차량에 저장된 글자를 그대로 넘기고 기본값이 없다(`supabase/migrations/0024_assigned_vehicle_share_base.sql:39`) — 서버는 안 고쳐도 같은 함수로 계산된다(`hydrateEmployedDriverCar.ts:22` → `driverSelfRevenue.ts`).

### 목표 상태 (기대 동작)
1. 새 기사 차량의 기본 필요경비율 49.9%, 산재보험료율 1.76%.
2. 옛 기본값(경비율 30.5, 요율 1.8)으로 저장된 차량은 새 기본값으로 읽어 계산하고, 차량 창에도 49.9·1.76으로 보인다(다시 저장하면 새 값으로 저장). 다른 값으로 직접 고친 차량(예 43.1, 0)은 그대로.
3. 사업소득자: 기사 몫 = 차주 몫 = 월보수액 × 요율 ÷ 2, 10원 미만 버림. 근로자: 차주 몫 = 월보수액 × 요율, 10원 미만 버림. 총액 = 두 몫의 합.
4. 예: 정산액 200,000(사업소득자, 산재·3.3% 켬) → 월보수액 100,200, 기사 880·차주 880, 3.3% 6,600, 실수령 192,520.
   월급 2,000,000 사업소득자 → 각 8,810, 실수령 1,925,190. 같은 월급 근로자 → 차주 17,630, 실수령 2,000,000.
   공단 예시(9,000,000원, 경비율 30.3·요율 1.8로 고친 차량) → 각 56,450.
5. 3.3% 원천징수 계산은 그대로(정산액 × 3.3%, 1원 미만 버림).
6. 달력·매출 기사 급여·기사 관리 정산 요약·연동 기사 본인 매출이 모두 같은 새 값(모두 `getDriverIncomeDeductions` 하나를 씀 — `grep -rn getDriverIncomeDeductions src`).
