보리 지시: C-3 착수지시서 작성 `[확인: 2026-11-05 보리 — "C-3 착수지시서 작성해줘"]`. C-3은 파일 저장(A)과 공유(B) 두 조각으로 나눈다 — 이번엔 **A(저장)만**. B(카카오톡·문자 공유)는 A가 만든 저장 함수를 이어 쓰므로 A 뒤에 따로 지시서를 쓴다. sot에 파일 저장 위치 규칙 없음(검색: 다운로드·저장 위치·Documents). 플레이북: 데이터 저장·동기화 경로는 안 바꿈(만든 파일을 휴대폰에 쓰는 것만) → 참고만.

### 쉬운 요약
- 앱에서 [PDF 다운로드]·[이미지 저장]·세금계산서 엑셀·데이터 백업을 누르면 지금은 "저장했습니다"만 뜨고 실제 파일은 아무 데도 안 생긴다. 이걸 휴대폰 "문서" 폴더 안 "운행일지" 폴더에 실제로 저장되게 한다.
- 웹사이트(컴퓨터·휴대폰 브라우저)는 지금과 똑같이 내려받기 된다.

### 현재 상태 (코드 확인)
- 내려받기 코드가 4곳에 따로 있다. 모두 파일을 임시 주소로 만들어 숨은 링크를 누르는 방식:
  - `src/features/documents/api/reportExport.js` 86~95줄 `downloadFile` — 운송비 내역서·일상점검표 PDF·이미지(`hooks/useFileDownload.js` 20줄이 부름).
  - `src/features/documents/api/taxInvoiceExcel.js` 28~37줄 — 세금계산서 엑셀(`ui/TaxInvoiceTab.jsx` 134줄).
  - `src/features/account/ui/DataDownloadModal.jsx` 19~29줄 `saveJsonFile` — 회원 데이터 다운로드.
  - `src/features/settings/ui/AppSettingsBackupSection.jsx` 42~51줄 — 비회원 백업.
- Capacitor 앱 화면은 이 링크 내려받기를 처리하지 않는다(Capacitor 안드로이드 코드에 내려받기 처리 없음 — `@capacitor/android` 검색: DownloadListener 없음). 에뮬레이터에서 [PDF 다운로드] → [저장]을 눌러도 오류 없이 끝나고 `/sdcard/Download`·`/sdcard/Documents`에 파일이 없음(2026-11-05 확인).
- 비회원 백업은 파일을 쓰기 **전에** "백업함"으로 표시한다(`AppSettingsBackupSection.jsx` 39줄 `markBackupDone`). 그래서 지금 앱에서는 파일이 없는데 "마지막 백업: 오늘"로 보인다.
- 파일 불러오기(백업 불러오기의 파일 고르기 창)는 Capacitor가 처리한다(`BridgeWebChromeClient.java` `onShowFileChooser`) → 이번 범위 아님.

### 목표 상태 (기대 동작)
1. 앱에서 저장 4종(내역서·점검표 PDF/이미지, 세금계산서 엑셀, 회원 데이터, 비회원 백업)을 누르면 휴대폰 `문서(Documents)/운행일지/` 폴더에 그 파일 이름 그대로 저장된다. 같은 이름이 있으면 새 파일로 덮어쓴다.
2. 앱에서 저장되면 알림 끝에 위치를 붙인다: 예 "PDF를 저장했습니다. 내 파일 > 문서 > 운행일지에서 볼 수 있어요." 실패하면 지금의 실패 알림 그대로.
3. 웹 브라우저에서는 지금과 같은 내려받기·같은 알림(바뀌는 것 없음).
4. 비회원 백업의 "마지막 백업" 표시는 파일 저장이 성공한 뒤에만 바뀐다.
5. 안드로이드 10 이하 휴대폰은 처음 저장할 때 저장 권한을 묻는다(11 이상은 묻지 않음). 거절하면 실패 알림.
