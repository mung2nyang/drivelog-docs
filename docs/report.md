> **진행(2026-10-14):** 착수 승인. `money.js` 54→62, `CallDetailForm.jsx` 200 유지. 테스트 새 4개, `npm test` 865+378 통과(기존 기대값 변경 없음), `typecheck` 통과.
> 개발 서버(실제 계정 로그인 상태): 운송료 20,000,000 → [저장] → 확인 창 문구 그대로 확인 → 취소 → 입력 창·값 그대로 → 입력 창도 취소(저장 안 함).

43-B(`de839c5`)에 이어서. 보리 결정(2026-10-14): **운송료만, 1,000만원 넘으면 경고**. 정비 비용 등 다른 금액은 천만원이 넘는 일이 흔해 경고하지 않는다. 근거: `docs/roadmap.md` 43번(검수 때 3,500억원이 경고 없이 저장됨).

### 쉬운 요약
- **무엇을:** 콜 상세 운송료가 1,000만원을 넘는 채로 [저장]을 누르면 "운송료가 N원으로 1,000만원을 넘어요. 금액이 맞나요?" 확인 창을 띄운다.
- **고르면:** [확인] → 지금처럼 저장. [취소] → 저장하지 않고 입력 창이 그대로 남아 고칠 수 있다.
- **달라지는 점:** 0을 몇 개 더 쳐서 생기는 엉뚱한 금액을 저장 전에 한 번 거른다. 1,000만원 이하는 지금과 똑같다.

### 현재 상태 (코드 확인)
- 콜 상세 [저장] 버튼: `components/day-log/CallDetailForm.jsx:197` `onClick={() => onSave(draft)}` — 금액 확인 없이 바로 저장 흐름(`DayLogPage.jsx:114` `handleSaveCall`)으로 간다. 새 입력·수정 모두 이 버튼 하나.
- `CallDetailForm.jsx` 200줄, `DayLogPage.jsx` 233줄 — 둘 다 줄을 늘리면 안 된다.
- 운송료 값은 43-A 이후 항상 쉼표 정수 글자(예: "12,000,000").
- 테스트 영향 미리 찾음: 1,000만원 넘는 운송료를 저장하는 테스트 없음(검색: 테스트 파일의 8자리 이상 금액), 공용 시험 데이터 최대 999,999원. 기존 기대값은 안 바뀔 것으로 본다.

### 목표 상태 (기대 동작)
1. 운송료 > 10,000,000원(1,000만원 **초과**)이고 [저장]을 누르면 확인 창.
2. [확인] → 저장(지금과 같음). [취소] → 저장 안 함, 입력 창·입력값 그대로.
3. 정확히 1,000만원 이하, 운송료 비어 있음 → 확인 창 없이 지금처럼 저장.
4. 새 입력·기존 카드 수정 둘 다 같다.
5. 다른 금액 칸(정비 비용·단가·월급 등)은 경고 없음.
