### 쉬운 요약
- **무엇을:** 지금 "화면을 불러오지 못했습니다 / 다시 시도" 안내(로드맵 33)는 로그인한 뒤 화면에만 있다. 이걸 로그인 화면·처음 정보 입력(환영·온보딩) 화면까지 넓힌다.
- **왜:** 그 화면들에서 그리다 오류가 나면 지금은 **하얀 빈 화면**만 남는다. 처음 쓰는 사람이 가장 먼저 보는 화면이라 더 위험하다.
- **달라지는 점:** 오류가 나도 빈 화면 대신 같은 안내와 [다시 시도] 버튼이 보인다. 오류가 없으면 아무것도 안 바뀐다.

### 현재 상태 (코드 확인)
- 안내 부품 `components/PageLoadErrorBoundary.jsx`(41줄): 화면 그리다 오류 → "화면을 불러오지 못했습니다. 잠시 후 다시 시도해 주세요." + [다시 시도](새로고침). 다른 화면으로 가면(`resetKey` 바뀜) 풀린다.
- 씌운 곳은 로그인 뒤 화면 하나뿐: `app/AppShell.jsx:132` `<PageLoadErrorBoundary resetKey={location.pathname}>`.
- `app/App.jsx:57-107` `<Routes>` 아래 `/auth`(로그인)·`/welcome`(처음 정보)·`/onboarding`(첫 설정)·`/app/*`(로그인 뒤) — 앞의 셋은 안내 없이 그대로 그린다. `App.jsx` 맨 위에서 오류가 나면 앱 전체가 비어 버린다.
- 업데이트 뒤 옛 화면 파일을 못 받는 경우는 `lib/chunkReload.js`가 한 번 새로고침하고, 그래도 안 되면 위 안내로 넘긴다(로그인 뒤 화면만 해당).
- "어디서도 안 잡힌 오류"(버튼 누름 처리·비동기 처리 중 오류)를 받는 앱 전체 장치는 없다(`unhandledrejection`·`window error` 검색 0건) — 아래 질문 1.

### 목표 상태 (기대 동작)
1. `App.jsx`의 `<Routes>` 전체를 `PageLoadErrorBoundary`(`resetKey` = 지금 주소)로 감싼다. 로그인·환영·온보딩 화면에서 그리다 오류가 나면 안내 + [다시 시도].
2. 다른 주소로 이동하면 안내가 풀린다(지금 부품 동작 그대로).
3. 로그인 뒤 화면은 지금처럼 `AppShell` 안쪽 안내가 먼저 잡는다(하단 메뉴 유지). 바깥 안내는 그 안쪽도 못 잡은 경우의 마지막 그물.
4. 오류가 없으면 화면·동작·속도 모두 지금과 같다.
5. 안내 모양·문구는 지금 부품 그대로(새 화면 디자인 없음).
