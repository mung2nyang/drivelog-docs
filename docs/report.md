## 123-C 운송비 내역서 CSS(`report.css` 257줄) 나누기 `[x]`

로드맵 123(`docs/roadmap.md` 605행, ⑥). 보리가 지시서 작성을 지시했다(2026-11-02 "응"). 이번에는 C(`report.css`)만 한다. 123-B와 같은 방식으로, 원래 순서대로 잘라 옮기기만 한다.

### 쉬운 요약
- 운송비 내역서 화면의 꾸밈 파일이 257줄이다. "~250줄까지 허용" 예외 표시가 있지만 그것도 넘었다.
- 이 파일을 두 파일로 나눈다. 아래쪽 84줄은 PDF로 내려받을 때만 쓰는 인쇄용 꾸밈이라 따로 뗀다.
- 글자 하나 바꾸지 않고 옮기기만 한다. 화면 모양과 내려받은 PDF 모양은 그대로다.

### 현재 상태 (코드 확인)
- `src/features/documents/ui/report.css`는 257줄, 규칙 덩이 54개다.
- 네 파일이 이 CSS를 불러온다(`src` 전체 검색).
  - `ReportPage.jsx` 19행
  - `ReportDetailView.jsx` 6행
  - `ReportSummaryContent.jsx` 4행
  - `ShareFileModal.jsx` 3행(내역서 공유와 일상점검표 공유 둘 다 씀)
- 빌드에서는 서류 발급 화면 묶음 `DocumentIssuePage-*.css` 하나에 들어간다.
- 174~257행은 모두 `body.pdf-export-mode`로 시작하는 인쇄용 규칙이다. 이 표시는 PDF를 그리는 동안에만 붙는다(`api/reportExport.js` 77·81행).
- 시험 하나가 이 파일을 직접 읽는다. `ReportDetailView.test.js` 127~137행이다. 확인하는 글자는 모두 5~111행에 있으므로 `report.css`에 그대로 남는다.
  - `.info-table th` 가운데 정렬
  - `.report-table td` 가운데 정렬
  - `.report-top-card`
  - `.report-pdf-actions .theme-toggle-btn`
  - 없어야 할 글자(`.detail-amount-cell` 오른쪽 정렬 등)
- 머리 주석(1~3행)에 §6 예외 표시와 옮긴 경위("side-menu.css에서 분리", 불러오는 파일 목록)가 있다.

### 목표 상태 (기대 동작)
1. 두 파일로 나뉘고, 둘 다 200줄 이하다. §6 예외 표시는 필요 없어져서 뺀다.
2. 규칙 내용(선택자, 속성, 값)과 앞뒤 순서가 한 글자도 바뀌지 않는다. 바뀌는 것은 파일 위치, 머리 주석, 불러오기 줄뿐이다.
3. 빌드한 앱의 CSS 파일들이 바꾸기 전과 글자까지 같다.
4. 내역서 화면(요약, 세부, 공유 창)과 PDF 그리기 상태에서 모든 요소의 계산된 스타일이 바꾸기 전과 같다.
5. CI(verify, db-test, deploy)가 초록이다. `ReportDetailView.test.js`의 CSS 시험도 그대로 통과한다.

### 건드릴 파일
- `src/features/documents/ui/report.css`(남김): 지금 5~172행. 위 카드, 정보 표, 내려받기 버튼 줄, 공유 창, 내역 표, 요약 줄, 좌우 나눔이다. 머리 주석을 바꾸고 173~257행을 떼어 낸다.
- `src/features/documents/ui/report-pdf-export.css`(새 파일): 지금 174~257행. PDF 그리기 상태의 색, 여백, 표 선, 숨길 것이다. 174행에 이미 있는 주석 `/* PDF 출력 모드 — 네비게이션 숨김 + 표/요약 인쇄용 색·여백 */`이 첫 줄이 되므로 새 주석은 넣지 않는다.
- JSX 네 파일(`ReportPage.jsx`, `ReportDetailView.jsx`, `ReportSummaryContent.jsx`, `ShareFileModal.jsx`): `import './report.css'` 바로 아래에 `import './report-pdf-export.css'` 한 줄씩을 더한다.
  - 네 파일에 다 넣는 이유: 빌드는 `report.css`를 처음 만나는 자리에 넣는데, 그 자리가 어느 파일인지는 불러오는 길 순서로 정해진다. 네 곳 모두에서 두 줄을 붙여 두어야 어느 쪽이 먼저든 두 파일이 원래 순서대로 이어 붙는다.
  - `ReportPage.jsx` 한 곳에만 넣는 방법도 있지만, 그러면 사이에 다른 CSS가 끼어 순서가 바뀔 수 있다(`ReportPage.jsx`가 14행에서 먼저 불러오는 `ReportDetailView.jsx`가 `report.css`를 먼저 부른다). 그러면 목표 3을 증명할 수 없어서 고르지 않는다.
  - 인쇄용 규칙은 PDF를 그리는 동안에만 켜지므로, 공유 창에서 함께 불러와도 평소 화면에는 닿지 않는다.
- `report.css` 머리 주석 최종 문구(한 줄): `/* 운송비 내역서 화면: 위 카드, 정보·내역 표, 요약 줄, 공유 창. */`
- 공용 영향 목록: `.info-table`, `.report-table`, `.summary-row`, `.report-page-wrap .summary-card` 같은 규칙이 다른 화면과 겹칠 수 있다. 이번에는 내용, 순서, 들어가는 묶음이 모두 그대로이므로 목표 3의 빌드 비교로 영향이 없음을 확인한다.

### 안 건드릴 것
- 규칙 내용, 클래스 이름, JSX의 className은 바꾸지 않는다.
- 안쪽 주석(25·84·108·174행)은 글자 그대로 옮긴다.
- `ReportDetailView.test.js`는 바꾸지 않는다. 확인하는 글자가 모두 `report.css`에 남는다.
- 123-D(`daily-inspection.css`)는 건드리지 않는다.

### 검증
- 자동 검사: CI(lint, 타입, 시험, 빌드, 의존 검사)가 돌린다.
- 옮기기 확인: 머리 주석을 뺀 두 파일을 이어 붙인 것이 바꾸기 전 5~257행과 같은지 비교한다. 순서까지 같아야 한다(54덩이).
- 빌드 비교: 바꾸기 전과 뒤에 각각 `npm run build`를 한다. 나온 CSS 파일 전부의 이름과 해시가 같은지 비교한다.
- 화면 확인: 로그인 탭(getdrivelog.com)에서 바꾸기 전 배포본의 지문을 뜨고, push·배포 뒤 같은 상태에서 다시 떠서 비교한다. 상태는 아래 넷이다.
  - 서류 발급의 운송비 내역서 요약 보기
  - 세부 보기
  - 공유 창을 연 상태(보내기는 누르지 않음)
  - 요약 보기에서 PDF 그리기 표시(`pdf-export-mode`)만 잠깐 붙인 상태. 내려받기는 누르지 않고, 지문을 뜬 뒤 바로 뗀다.
