## Capacitor 전환 C-6 — 다른 앱 다녀오면 화면이 처음으로 `[x]`

2026-11-06 보리 요청("c-6착수지시서 작성해줘, 재현필요하면 진행하고 작성해"). 승인 `[확인: 2026-11-06 보리 — "응 맞겨,서류발급도 되살려,착수지시서 확정 작업진행해"]`. 근거: 로드맵 "Capacitor 전환" C-6과 그 원인 조사 ①~③(2026-11-06). 앞 조각 C-5(뒤로가기)와 같이 앱 쪽 처리만 더하고 웹은 그대로. 1.0.3은 C-8까지 끝낸 뒤 한 번에 올림.

### 쉬운 요약
- 앱에서 인쇄·공유 같은 다른 앱에 갔다 오면, 가끔 보던 서류 화면이 아니라 홈이 나옵니다. 다른 앱에 가 있는 동안 휴대폰이 메모리를 비우려고 우리 앱을 정리하면, 앱이 처음부터 다시 열리기 때문입니다.
- 앱이 정리되더라도, 돌아왔을 때 보던 화면 주소로 다시 열리게 합니다. 서류 발급 화면은 보던 탭과 달까지 그대로 나오게 합니다.

### 현재 상태 (코드 확인·재현)
- 재현(에뮬레이터, 정식 v4 1.0.3, 비회원): 서류 발급 → 운송비 내역서 → 공유 → PDF로 보내기 → Print → 뒤로 5번 반복. 5번 모두 그대로 운송비 내역서였고, 앱·화면 프로세스 번호도 그대로였음. 메모리가 넉넉하면 생기지 않음.
- 원인 ① 직접 확인: 같은 화면에서 홈으로 나간 뒤 앱 프로세스를 정리(`adb shell am kill`)하고 다시 열면 홈이 나옴. Capacitor가 화면 주소를 기억하지 않고 처음 주소부터 다시 엶(`BridgeActivity.java` `onSaveInstanceState`는 플러그인 호출만 저장, `MainActivity.java`는 빈 껍데기 5줄).
- 원인 ②(화면 프로세스만 죽음): 이 에뮬레이터는 관리자 권한이 없어 직접 일으키지 못함. Capacitor는 처리하지 않으므로(`BridgeWebViewClient.java` `onRenderProcessGone`이 듣는 곳 없으면 `false`) 안드로이드가 앱을 통째로 닫음 → ①과 같은 결과.
- 원인 ③: 서류 발급 탭과 보는 달은 화면 안 값뿐(`DocumentIssuePage.jsx:33-34` `useState`)이라 주소에 없음 → 주소만 되살려도 기본 탭·이번 달로 나옴.
- 다시 열 때 주소가 `/app/...`이면 앱은 홈으로 옮기지 않고 그 화면에 둠(`bootHomeGuard.js` `isAlreadyInAppOnBoot`, 비회원·회원 둘 다 `useAppSession.js`에서 이 판단을 씀) → 주소만 되살리면 그 화면이 나옴.
- 돌아올 때 화면을 다시 그리게 하는 우리 코드는 없음(`visibilitychange`는 `dayDraftActivity.ts` 일지 임시 저장뿐, `onAuthStateChange` 검색 0건).

### 목표 상태 (기대 동작)
1. 앱에서 다른 앱에 가 있는 동안 우리 앱이 정리돼도, 돌아오면 보던 화면이 나온다(서류 발급이면 서류 발급).
2. 서류 발급 화면은 보던 탭(세금계산서·운송비 내역서·일상점검표)과 보던 달까지 그대로 나온다.
3. 최근 앱 목록에서 앱을 밀어서 끈 뒤 새로 켜면 지금처럼 홈부터(안드로이드가 기억을 지움).
4. 웹(크롬 탭·바탕화면 설치)에서 서류 발급 탭·달을 바꾸면 주소에 남는 것 말고는 지금과 같다. 탭·달을 바꿔도 뒤로가기 기록은 늘지 않는다(주소를 바꿔 끼움, 달력과 같은 방식).
