`docs/sot.md` 확인: `:539` "로그인 사용자의 업무 데이터(…계산서…)는 저장은 서버 1회 성공 후에만 Store 반영, 실패 시 큐 없이 즉시 토스트 중단." `:544` 로그인 저장 실패 토스트 문구 "저장에 실패했습니다. 네트워크 상태를 확인해 주세요." 세금계산서 저장 안내 시점에 대해 따로 정한 규칙은 없습니다.

### 쉬운 요약
- **무엇을:** 세금계산서 "작성 내용 저장"과 "발급 완료 표시/되돌리기"가 서버 저장 결과를 기다린 뒤에 안내합니다. 실패하면 "저장에 실패했습니다…"를 띄우고, 작성 창은 열어 둡니다.
- **왜:** 지금은 서버 저장을 기다리지 않고 바로 "저장했습니다"를 띄우고 창을 닫습니다. 저장이 실패하면 입력한 사업자번호 등이 사라지고, "발급 완료"도 성공 안내 뒤 조용히 "작성 전"으로 남습니다.
- **달라지는 것:** 성공이면 지금과 같습니다. 실패하면 실패 안내가 뜨고 입력 내용이 창에 남아 다시 저장할 수 있습니다.

### 현재 상태 (코드 확인)
- `lib/taxInvoiceActions.js:50-52` `saveTaxInvoiceDraft` — `persist(…)`를 기다리지 않고 성공 안내·`return true`(창 닫기).
- `lib/taxInvoiceActions.js:74-79` `changeTaxInvoiceStatus` — `persist(…)`를 기다리지 않고 "발급 완료로 표시했습니다"/"처리 전 상태로 되돌렸습니다" 안내.
- `components/documents/TaxInvoiceTab.jsx:81-83` `persist`는 `await saveInvoices(…)`인 비동기 함수입니다. 실패하면 약속이 거절되는데, 위 두 곳이 받지 않아 처리되지 않은 오류로 남습니다.
- `lib/invoices.js:26-40` `saveInvoices` — 로그인은 서버(`syncTaxInvoices`) 성공 뒤에만 `commitInvoices`(sot `:539`대로). 비회원은 기기 저장(`commitInvoices`, 저장 공간 부족이면 오류).
- 거래처 세무 정보 저장(`:31-48` `requestClientTaxInfo`)은 이미 결과를 기다리고, 실패하면 안내 후 창을 엽니다(그대로 둠).
- 부르는 곳은 `TaxInvoiceTab.jsx:96`(작성 저장)·`:112`(상태 바꾸기) 한 화면뿐입니다.

### 목표 상태 (기대 동작)
1. 작성 내용 저장: 서버(비회원은 기기) 저장이 성공해야 "세금계산서 작성 내용을 저장했습니다." 안내와 창 닫기를 합니다.
2. 작성 내용 저장이 실패하면 "저장에 실패했습니다. 네트워크 상태를 확인해 주세요."를 띄우고 창은 열린 채 입력 내용이 남습니다.
3. 발급 완료 표시/되돌리기: 저장이 성공해야 지금 안내를 띄웁니다. 실패하면 위 실패 안내만 띄우고 화면 상태는 저장 전 그대로입니다.
4. 처리되지 않은 오류가 남지 않습니다(실패를 받아 안내로 바꿈).
5. 거래처 세무 정보 저장은 지금과 같습니다. 그것이 성공하고 세금계산서 저장만 실패하면, 거래처 정보는 저장된 채 위 실패 안내가 뜹니다.
