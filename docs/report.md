## 로드맵 68 비회원 백업 복원도 앱 켤 때와 같은 형식 검사 `[x]`

코드 리뷰(2026-10-14)로 로드맵 68번 등재 `[확인: 2026-10-14 보리]`, 순서 ①(데이터 저장·유실). 67번 다음. 플레이북 트리거 해당(`localStorage`에 쓰는 경로) — `docs/testing-playbook.md` 열람함.

### 쉬운 요약
- **무엇을:** 비회원이 백업 파일을 복원할 때, 앱을 켤 때 쓰는 엄격한 형식 검사를 똑같이 거치게 합니다.
- **왜:** 지금은 겉모양만 보고 저장해서, 안쪽 내용이 앱 형식과 다른 파일도 "복원했습니다"가 뜹니다. 그런데 다음에 앱을 켜면 "기록을 불러오지 못했습니다" 화면만 나오고 빠져나갈 길이 없습니다.
- **달라지는 것:** 이런 파일은 복원할 때 바로 "백업 파일이 손상되었거나…" 안내가 뜨고, 기존 기록은 그대로 남습니다. 앱 형식에 맞는 백업(이 앱에서 내려받은 파일)은 지금처럼 복원됩니다.

### 현재 상태 (코드 확인)
- 복원(`lib/guestBackup.js:96-141`)은 칸이 목록·묶음인지, 하루 기록이 묶음인지만 봅니다. 차량·거래처 안의 칸 이름, 하루 기록의 숫자·콜 상세 모양은 보지 않습니다. `subWorkData`는 안쪽을 아예 안 봅니다(`:137-141`).
- 저장 단계(`store/owner-state.js:104` `replaceOwnerState` → `commitBatch`)에서도 형식 검사가 없습니다(`app-store.js`에 `matchesDomainSchema`·`isPersisted` 검색 0건).
- 앱을 켤 때(`store/owner-state.js:29` `initializeOwnerFromPersist`)는 칸마다 `readPersistDomain`(→ `matchesDomainSchema`, 정해진 칸 밖이 있으면 거절)과 `readLogWorkData`(→ `parsePersistedWorkDataMap`)로 검사합니다. 하나라도 실패하면 막기 화면(32번)이 뜹니다.
- 회원 불러오기(`lib/memberRestore.js:41`)는 이미 같은 `parsePersistedWorkDataMap`을 쓰고, 틀리면 파일 전체를 거절합니다.
- **재현함:** 임시 시험(코드 수정 없음)에서 차량에 `oldField`, 하루 기록에 `memo`가 섞인 백업을 넣었습니다. `applyGuestBackupData` → `{ok:true}`, 이어서 `initializeOwnerFromPersist('guest')` → `false`(막기 화면)가 나왔습니다.

### 목표 상태 (기대 동작)
1. 차량·거래처·기사·지출·세금계산서·설정·개인정보 칸은 앱 켤 때와 같은 검사(`matchesDomainSchema`)를 통과해야 복원됩니다.
2. `workData`·`workLogs` 안의 차량별 일지, `subWorkData` 안의 일지는 모두 `parsePersistedWorkDataMap`을 통과해야 복원됩니다. 저장은 검사를 통과해 정리된 값(옛 `'off'` 표기 → `{ isOff: true }`)으로 합니다.
3. 하나라도 틀리면 파일 전체를 거절합니다(보리 결정 2026-10-14: 맞는 부분만 골라 복원하지 않음). 안내는 지금 문구 그대로("백업 파일이 손상되었거나 운행일지 백업 파일이 아닙니다.")이고, 기존 기록·저장소·화면은 하나도 안 바뀝니다(저장 0회).
4. 이 앱에서 내려받은 백업은 지금처럼 복원됩니다(기존 왕복 테스트 통과).
5. 복원에 성공했으면 앱 켤 때 검사도 반드시 통과합니다. 테스트로 `initializeOwnerFromPersist('guest') === true`를 확인합니다.

### 건드릴 파일
- `react-app/src/lib/guestBackup.js` — `:96-141`의 겉모양 검사를 `matchesDomainSchema`·`parsePersistedWorkDataMap` 검사로 바꾸고, 스냅샷에는 검사를 통과해 정리된 일지를 넣습니다. 새로 넣을 주석(최종 문구): `// 앱 켤 때 검사(owner-state.js)와 같은 규칙 — 통과 못 하면 다음 실행이 막기 화면에 갇힌다.`
- `react-app/src/lib/guestBackup.test.js` — 테스트를 추가합니다. ①차량에 정해진 칸 밖 내용 → 거절, 저장소 그대로 ②하루 기록에 틀린 칸·틀린 콜 상세 → 거절 ③`subWorkData` 안쪽이 틀림 → 거절 ④설정에 정해진 칸 밖 내용 → 거절 ⑤정상 복원 뒤 `initializeOwnerFromPersist('guest') === true`.
- 공용 값 변경 없음. 검사 함수는 가져다 쓰기만 하고 고치지 않습니다.

### 안 건드릴 것
- `store/persistDomainSchema.js`·`persistDayRecord.js` 검사 규칙 — 그대로 씁니다. 앱 켤 때와 같아야 하기 때문입니다(사용처: `persistDomainRead.js:48`, `persist.js:74`).
- `store/owner-state.js`·`app-store.js` — 저장 경로는 안 바꿉니다.
- `components/AppSettingsBackupSection.jsx` — 오류 문구는 `res.error`를 그대로 보여 주므로 안 바꿉니다(`:78-82`).
- 회원 불러오기(`memberRestore*.js`) — 이미 같은 검사를 씁니다(`memberRestore.js:41`).
- 알림 숨김·빈 날 삭제 목록 복원 — 로드맵 78번으로 따로(보리 결정 2026-10-14, ⑤ 불편).

## 68-1 수정 착수지시서 — 기사 차량 일지가 복원 뒤 기기에 저장 안 됨 `[x]`

68번 작업 중 새 테스트 ⑤가 실패해서 멈췄습니다(AGENTS §3-2). 코드는 68번까지 고친 상태로 두고 대기 중입니다.

### 쉬운 요약
- **무엇이 실패했나:** 비회원 백업을 복원하면 기사 차량 일지가 화면에는 보입니다. 그런데 기기에는 저장되지 않아서, 앱을 다시 켜면 사라집니다. 메인 차량 일지는 정상입니다.
- **68번 때문인가:** 아닙니다. 68번 전부터 있던 문제입니다. 고치기 전 코드로 돌려도 같습니다.
- **고치면:** 복원할 때 기사 차량 일지도 메인 일지와 같은 한 번의 저장으로 기기에 씁니다.

### 현재 상태 (코드 확인)
- 실패: `guestBackup.test.js` "68: 복원에 성공하면…" — 다시 읽은 기사 차량(`22나2222`) 일지가 `undefined`(기대 3)였습니다.
- 재현(임시 시험): 빈 기기에 메인·기사 차량 일지가 든 백업을 복원했습니다. 화면(메모리)에는 기사 차량 일지가 있고, 기기의 메인 키에도 저장됐습니다. 하지만 기사 차량 키 `reactPracticeWorkData:guest:log:22나2222`는 `null`이었습니다.
- 원인: `replaceOwnerState`(`store/owner-state.js:104`)가 기기에 쓰는 건 메인 일지(`workData`)뿐입니다. 기사 차량 일지는 `replaceWorkLogs`로 메모리에만 넣습니다(`app-store.js:159-161`). 기사 차량 키를 쓰는 통로 `extraWrites`(`app-store.js:150`)를 넘기지 않기 때문입니다.
- 기존 왕복 테스트가 이 문제를 못 잡은 이유: 복원 전에 같은 기사 차량 키를 손으로 미리 써 둡니다(`guestBackup.test.js:89`). 그리고 복원 뒤에는 메모리만 봅니다.

### 목표 상태 (기대 동작)
1. 복원할 때 백업의 기사 차량 일지마다 해당 기기 키를 메인 일지와 **같은 한 번의 저장(전부 되거나 전부 안 되거나)**으로 씁니다.
2. 지금 기기에 있는 기사 차량 일지 중 백업에 없는 차량의 키는 같은 저장에서 지웁니다. 복원은 통째로 바꾸기라 화면에서는 이미 사라지기 때문입니다. 남겨 두면 같은 번호 차량을 다시 만들 때 옛 일지가 되살아납니다. 차량 삭제(`lib/vehicleDeletion.js:51`)와 같은 방식입니다.
3. 저장이 실패하면 기기·화면 모두 복원 전 그대로이고, 안내는 지금 문구 그대로입니다(`guestBackup.js` catch).
4. 테스트 ⑤(복원 뒤 앱 켤 때 검사 통과 + 기사 차량 일지 그대로)가 통과합니다. 테스트를 하나 추가합니다: 백업에 없는 기사 차량 키는 지워짐.

### 건드릴 파일
- `react-app/src/store/owner-state.js` — `replaceOwnerState` 옵션에 `extraWrites`를 더해 `commitBatch`에 그대로 넘깁니다(약 +2줄). 다른 호출처 2곳(`lib/hydrate.js:78·173`, `persist: false`)은 넘기지 않으므로 동작 변화가 없습니다.
- `react-app/src/lib/guestBackup.js` — 기사 차량 키 쓰기·지우기 목록(`storageKeyForLog`)을 만들어 넘깁니다(약 +10줄).
- `react-app/src/lib/guestBackup.test.js` — 위 테스트 1개를 추가합니다.

### 안 건드릴 것
- `store/app-store.js` `commitBatch` — `extraWrites` 통로가 이미 있습니다(`:150`, 비회원만 기기에 씀).
- 새 저장 키·새 장치 없음 — 기존 기사 차량 키(`persist.js:41` `storageKeyForLog`)와 기존 통로만 씁니다.

### 검증
- 로컬 `npm test`. 새 테스트 2개는 고치기 전 실패를 확인합니다. CI verify 초록.
- 브라우저(비회원): 기사 차량 운행 1건 → 백업 → 그 일지 삭제 → 복원 → 새로고침 뒤에도 기사 차량 운행이 남아 있으면 성공입니다.

### 파일 길이
- `store/owner-state.js` 132줄 → 약 134줄.
- `lib/guestBackup.js` 145줄(68번 반영) → 약 158줄.

### 실패 시 처리
- 새 저장 장치 없음. 실패하면 다시 수정 착수지시서를 쓰고 승인받습니다.

### 사용자 확인 방법
