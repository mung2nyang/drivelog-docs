### 쉬운 요약
- **무엇을:** 금액 칸에 "12345.6"을 치면 화면엔 친 그대로 보이다가, 저장되는 값은 반올림한 12,346원이 되게 한다.
- **왜:** 지금은 점(.)이 치는 순간 사라져서, 뒤에 친 6이 그대로 붙어 123,456원(10배)이 된다. 경고도 없다.
- **이번 범위:** 콜 상세의 운송료·산재보험료 칸(검수에서 나온 곳). 다른 금액 칸 9곳은 43-B에서 같은 부품으로 바꾼다.

### 현재 상태 (코드 확인)
- 금액 칸은 글자를 칠 때마다 `formatCurrencyInput`(`domain/money.js:25-28`)을 거친다. 이 함수는 숫자 아닌 글자를 전부 지운다(`parseCurrencyValue`, `:8-11`). 그래서 "12,345."의 점이 바로 사라지고, 다음에 친 "6"이 붙어 "123,456"이 된다.
- 콜 상세 운송료 칸 `components/day-log/CallDetailForm.jsx:136`, 산재보험료 칸 `CallDetailPaymentFields.jsx:48`.
- 저장되는 금액 글자는 점이 들어가면 안 된다. 저장 검사(`lib/callDetailSchema.js:42`)가 "쉼표 정수"만 받는다. 점이 들어간 값이 저장되면 그 사람의 데이터 불러오기 전체가 실패할 수 있다(2026-09-11 사고와 같은 종류). → **화면 칸에서만 점을 보여 주고, 폼에 넘기는 값은 항상 반올림된 정수**여야 한다.
- 같은 함수를 쓰는 금액 칸은 모두 11곳이다(차량 월급, 거래처 정액 수수료, 정비·주유·기타 비용·주행거리·보조금, 고정노선 단가·파렛트 단가, 부분 입금, 계기판).

### 목표 상태 (기대 동작)
1. 새 공용 금액 칸 부품 `CurrencyInput`:
   - 칸 안에는 친 글자를 그대로 보여 준다(예: "12,345.6", 점 하나까지).
   - 폼에는 매번 **반올림한 정수 금액 글자**만 넘긴다(예: "12,346"). 칸에서 나가면(포커스 해제) 화면도 "12,346"으로 정리된다.
2. 반올림 규칙: 소수 첫째 자리 기준 반올림(12,345.4 → 12,345, 12,345.5 → 12,346). 점이 두 개 이상이면 첫 점만 소수점으로 본다.
3. 콜 상세 운송료·산재보험료 칸이 이 부품을 쓴다. 지금처럼 쉼표가 붙고, 입력칸 X 버튼·숫자 자판도 그대로다.
4. 소수점을 안 쓰면 지금과 완전히 같다.
5. 저장되는 금액 글자에는 절대 점이 없다(저장 검사 통과).
