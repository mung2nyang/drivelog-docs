앞 슬라이스 35(`04a8de9`)는 "서버 저장 실패 중 나가기"를 막았고, 이번 건은 "아직 [저장]을 안 누른 입력 창"이 대상이다.

### 쉬운 요약
- **무엇을:** 운행일지에서 세부 입력 창(거래처·운송료 등)이나 정비/주유/기타 입력 창을 연 채로 위쪽 뒤로가기를 누르면, "입력 중인 내용이 저장되지 않았다"는 확인 창을 띄운다.
- **덤:** 다른 달(예: 2027년 1월) 일지에서 뒤로 가면 오늘 달(10월)이 아니라 **그 일지의 달** 달력으로 돌아가게 한다.
- **달라지는 점:** 실수로 뒤로가기를 눌러도 입력이 조용히 사라지지 않는다.

### 현재 상태 (코드 확인)
- 위쪽 뒤로가기는 `DayLogPage.jsx:93-95` `handleClose`를 거친다. 여기서는 `confirmLeaveIfUnsafe()`만 확인한다. 이 함수는 "서버·기기 저장이 깨졌을 때"만 확인 창을 띄운다(`durableWriteGuard.js:59-61`, `:73-76`).
- 세부 입력 창에 쓴 내용은 [저장]을 누르기 전까지 그 창 안에만 있다(`CallDetailForm.jsx:44` `useState`). 일지 기록에는 아직 안 들어가 있으므로, 위 확인에 걸리지 않고 그대로 사라진다. → **재현 내용과 일치**
- 정비/주유/기타 입력 창도 같은 구조다. 창 상태(`useExpenseForm.js:18-19` `kindPick`·`modalOpen`)도 [저장] 전까지는 창 안에만 있다.
- 달 문제: 일지를 닫을 때 갈 곳은 `workLogNavigation.js:18-24`가 정한다. 달력에서 들어왔으면 "한 칸 뒤로"(`navigate(-1)`) 간다. 이때 달력 주소에 `?y=&m=`가 남아 있으므로 원래 달로 돌아가야 한다(`CalendarPage.jsx:51-52`). 그런데 들어온 표시(`from`)가 없으면 `/app/calendar`로 바로 이동한다. 이 주소에는 달 정보가 없어 오늘 달이 된다(`calendarViewDate.js:13`). **검수 때 어느 경로로 들어갔는지는 아직 확인 못 함** — 착수 첫 단계에서 개발 서버로 재현해 확정한다.

### 목표 상태 (기대 동작)
1. 세부 입력 창이 열린 채 위쪽 뒤로가기 → 확인 창 "입력 중인 내용이 아직 저장되지 않았습니다. 그래도 나가시겠습니까?" 표시. [취소]하면 일지에 그대로 남고, 입력도 그대로 있다.
2. 확인 창에서 [확인] → 지금처럼 나간다(입력은 버려짐).
3. 정비/주유/기타 입력 창이 열린 채 위쪽 뒤로가기 → 1·2와 같다.
4. 입력 창이 닫혀 있으면 확인 창 없이 지금처럼 바로 나간다.
5. 서버 저장 실패 확인(35번)은 지금처럼 먼저 뜬다. 두 조건이 다 걸리면 확인 창이 차례로 두 번 뜰 수 있다(드문 경우).
6. 들어온 표시 없이 연 일지(새로고침·주소 직접 입력 등)를 닫으면 **그 일지 날짜의 달** 달력으로 간다(예: 2027-01-31 → 2027년 1월). 서브 차량 일지도 같다.
7. 달력·홈에서 들어온 일지를 닫는 동작("한 칸 뒤로")은 그대로다.
8. 재현해 보니 6번이 원인이 아니면, 코드를 고치지 않고 수정 착수지시서를 다시 쓴다.

### 사용자 확인 방법
1. 달력에서 다른 달(예: 2027년 1월)로 넘겨 31일을 누른다.
2. [운행 추가]로 세부 입력 창을 열고 거래처·운송료를 넣은 뒤 위쪽 ← 를 누른다 → 확인 창이 뜨면 성공. [취소] → 입력이 그대로 있다. 다시 ← → [확인] → **2027년 1월** 달력으로 돌아간다.
3. 정비 추가 창을 열고 ← → 같은 확인 창이 뜬다.
4. 입력 창을 다 닫고 ← → 확인 창 없이 나간다.
5. 일지 화면에서 새로고침한 뒤 ← → 그 일지의 달 달력으로 간다.
