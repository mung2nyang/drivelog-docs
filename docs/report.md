## 로드맵 67-B 지출 저장·점검표 읽기도 1,000줄 넘게 끝까지 받기 `[x]`

> 진행(2026-10-14): 코드 커밋 react-app `c1b28d5`. 테스트 1,292개 통과, 타입 검사·빌드 통과, 엄격 검사 경고 457개(늘지 않음). 새 테스트 E-1·E-2·I-1은 고치기 전 코드로 되돌리면 3개 모두 실패함을 확인. 개발 서버 시험 계정: 메인 차량(날짜 방식)과 연동 22가2222(항목 방식) 주유 추가·삭제가 서버에 맞게 반영됨. 점검표 전체 읽기 결과가 서버 직접 조회 개수(3장)와 같음. 처음 확인 때 주유 두 건을 같은 1ms 안에 만들어 번호가 겹쳐 한 건이 빠졌으나, 이는 확인 순서 탓으로 이번 수정과 무관(따로 만들면 정상). 보리 push, CI 초록(verify·deploy), 최종 승인(2026-10-14).

보리 지시(2026-10-14, 67-A 최종 승인 뒤 "67-B 착수지시서"). 근거: `docs/roadmap.md` 67번, 67-A(`c143e32`)에서 만든 `lib/fetchAllRows.js`를 나머지 곳에도 쓴다. 저장 경로라 `docs/testing-playbook.md` 확인.

### 쉬운 요약
- 67-A는 앱 켤 때 불러오기만 고쳤다. 지출을 저장하거나 점검표를 내려받기·불러오기 할 때도 서버에서 목록을 한 번만 받아서, 1,000줄이 넘으면 일부를 모른 채 저장한다.
- 이 세 곳도 1,000줄씩 끝까지 받게 한다.
- 끝나면 기록이 많아져도 지출 저장이 같은 항목을 두 번 넣거나 지운 항목을 남기지 않고, 점검표 불러오기가 이미 있는 점검표를 덮어쓰지 않는다.

### 현재 상태 (코드 확인)
- `lib/syncExpenseItems.js:41-45` `dailyLogIdsByDate`, `:82-87` `fetchRows`(연동 차량 지출 항목 단위 저장) — 한 번만 읽음. 잘리면: 서버에 있는 항목을 "없다"고 보고 다시 넣어 **중복**, 지운 항목은 못 찾아 **안 지워짐**(`:111-138`).
- `lib/syncExpenseRecords.js:26-33` `dailyLogIdsByDate`(메인·미연동 차량 지출) — 잘리면 하루 기록 id를 못 찾아 그날 하루 기록을 다시 저장(`:52-56` `upsertDailyLog`).
- `lib/dailyInspections.js:90-105` `fetchVehiclesDailyInspections` — 데이터 다운로드(`memberBackup.js:38`)와 회원 불러오기(`memberRestoreInspections.js:76`)가 씀. 잘리면 다운로드 파일에서 점검표가 빠지고, 불러오기는 이미 있는 날을 "없다"고 보고 **파일 값으로 덮어씀**(`saveDailyInspection`은 차량+날짜 덮어쓰기).
- `lib/fetchAllRows.js`가 이미 있음(67-A).

### 목표 상태 (기대 동작)
1. 위 4곳이 `fetchAllRows`로 1,000줄씩 끝까지 받는다. 정렬 끝에 `id`(이어 받을 때 중복·누락 방지).
2. 중간 묶음 오류면 지금처럼 그 저장·읽기를 실패로 던진다(일부만 받은 목록으로 저장하지 않음).
3. 1,000줄 이하면 요청 수·결과가 지금과 같다.
4. 저장 방식(무엇을 넣고 지우는지)은 그대로 — 받는 양만 달라짐.
