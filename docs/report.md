## 11-B 앱 연결 파일 assetlinks.json 배포 `[x]`

보리 요청(2026-11-03, 11-C 승인 뒤 다음 순서). 근거: 로드맵 11번 "도메인 루트 `/.well-known/assetlinks.json` 배포(주소창 없는 앱 화면의 조건)". 11-C(`d091df2`)에서 만든 업로드 키 지문을 쓴다. 이번엔 **11-B만** — 플레이 콘솔의 Play 앱 서명 키 지문은 콘솔에 앱을 올린 뒤에 나오므로 그때 같은 파일에 한 줄 더하는 작은 후속(11-B-2)으로 둔다.

### 쉬운 요약
- 설치한 운행일지 앱 위에 주소줄이 보이는 건, 사이트가 "이 앱은 우리 것"이라고 확인해 주는 파일이 없어서다.
- 그 파일(`assetlinks.json`)을 getdrivelog.com에 올린다. 배포 설정이 점(.)으로 시작하는 폴더를 빼고 올리고 있어서 설정 한 줄도 같이 고친다.
- 끝나면 앱을 다시 열었을 때 주소줄 없이 화면 전체가 앱이 된다. 웹 화면·기능은 그대로다.

### 현재 상태 (코드 확인)
- `https://getdrivelog.com/.well-known/assetlinks.json` 없음 — `react-app/public`에 `.well-known` 폴더 없음(`ls -A public`).
- 배포는 `.github/workflows/ci.yml` 84~86줄 `actions/upload-pages-artifact@v5`(`path: react-app/dist`). 이 도구는 `include-hidden-files` 기본값이 `false`라 점으로 시작하는 파일·폴더를 빼고 올린다(도구 설정 파일 `action.yml`의 `--exclude=.[^/]*` 확인). 그래서 `public/.well-known/`만 만들면 배포본에 안 실린다.
- 같은 이유로 지금 `public/.nojekyll`도 배포본에 빠져 있다(문제는 없음 — Actions 배포는 Jekyll을 안 돌림).
- 지문은 11-C 결과 `C:\dev\drivelog-keys\v1\assetlinks.json`에 있고, .aab 실제 서명과 같음을 확인함(`keytool -printcert`). 지문은 공개해도 되는 값이다(앱 파일에서 누구나 읽을 수 있음).

### 목표 상태 (기대 동작)
1. `https://getdrivelog.com/.well-known/assetlinks.json`이 리다이렉트 없이 200, `application/json`으로 열린다.
2. 내용은 11-C 파일과 같다 — `package_name` `com.getdrivelog.app`, 업로드 키 SHA-256 `26:7F:1D:...:4C:D8` 한 개.
3. 구글 확인 도구(Digital Asset Links API `statements:list`)가 이 연결을 읽어 낸다.
4. 보리 휴대폰에서 앱을 지우고 다시 깔면(또는 앱 데이터 삭제) 주소줄 없이 열린다.
5. 웹 화면·다른 배포 파일은 그대로다(`.nojekyll`이 같이 실리는 것 말고 바뀌는 파일 없음).

### 건드릴 파일
- `react-app/public/.well-known/assetlinks.json` — 새로 만듦(11-C 파일 그대로 복사).
- `react-app/.github/workflows/ci.yml` — "배포할 빌드 올리기"의 `with:`에 `include-hidden-files: true` 한 줄. 주석 최종 문구(한 줄): `# 앱 연결 파일(.well-known)도 올린다.`
- 영향 목록: 이 설정은 `dist` 안 점 파일 전부에 적용 — 지금 `dist`에 생기는 점 파일은 `public`의 `.nojekyll`과 새 `.well-known/` 둘뿐(`ls -A public`, Vite는 `public`을 그대로 복사).
