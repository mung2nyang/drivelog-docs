### 쉬운 요약
- 비회원이 백업 파일을 불러오면, 파일 안에 들어 있는 "닫은 알림 목록"과 "지운 날 목록"이 지금은 버려집니다. 이 두 가지도 다른 기록처럼 백업 시점 그대로 되살립니다.
- 하고 나면: 백업 전에 닫아 둔 알림(예: "오늘 운행일지가 비어 있습니다", "백업 권장")이 불러온 뒤에 다시 뜨지 않습니다.

### 현재 상태 (코드 확인)
- 백업 만들 때는 두 목록을 **넣는다**: `src/lib/guestBackup.js:15-25` `SLICE_DOMAINS`에 `dismissedNotifications`·`workDataDeletedDates` 포함.
- 불러올 때는 **안 쓴다**: 같은 파일 `applyGuestBackupData`(108~)가 두 키를 검사·반영하지 않음. 받는 쪽 `src/store/owner-state.js:82-127` `OwnerSnapshot`·`replaceOwnerState`에도 두 칸이 없음.
- 형식 검사는 이미 있다: `src/store/persistDomainSchema.js:110,118` `matchesDomainSchema`(닫은 알림 = 글자 목록, 지운 날 = 날짜 → 시각).
- 저장 경로도 이미 있다: 두 목록 모두 `commitBatch`로 기기에 저장됨(`store/commitHelpers.js:99,107`).
- 닫은 알림이 실제로 쓰이는 곳: `lib/notifications.js` `collectNotifications`(비회원은 "오늘 운행일지가 비어 있습니다" `today:날짜`, "백업 권장" `backup:시각`).
- 지운 날 목록이 쓰이는 곳: 로그인 계정 서버 불러오기(`lib/hydrate.js:129`)가 지운 날을 되살리지 않게 거르는 데만 씀. **비회원 화면에는 보이는 영향이 없음**(비회원은 서버 불러오기 없음, 가입 시 이관 코드 없음 — `docs/sot.md` 591~592).

### 목표 상태 (기대 동작)
1. 백업 파일에 닫은 알림 목록이 있으면, 불러온 뒤 그 목록이 백업 시점 그대로 된다(지금 기기 목록과 합치지 않고 교체 — 차량·거래처 등 다른 기록과 같은 방식).
2. 백업 파일에 지운 날 목록이 있으면, 불러온 뒤 그 목록이 백업 시점 그대로 된다(교체).
3. 두 목록이 없는 옛 백업 파일은 지금처럼 불러와지고, 기기에 있던 두 목록은 그대로 둔다.
4. 두 목록 모양이 틀린 파일은 다른 기록과 같이 "백업 파일이 손상되었거나 운행일지 백업 파일이 아닙니다."로 거부하고 아무것도 바꾸지 않는다.
5. 두 목록만 들어 있고 다른 기록이 하나도 없는 파일은 지금처럼 백업 파일이 아니라고 거부한다.
6. 앱을 다시 켜도 복원된 두 목록이 남아 있다(기기에 저장).

### 사용자 확인 방법 (배포 뒤, 비회원)
1. 알림 → "오늘 운행일지가 비어 있습니다" 또는 "백업 권장" 알림을 닫는다.
2. 앱 설정 → 데이터 관리 → 백업 파일 저장.
3. 다른 휴대폰이나 다른 브라우저의 비회원 화면에서 → 앱 설정 → 데이터 관리 → 그 파일 불러오기.
4. 알림을 열었을 때 1번에서 닫은 알림이 **안 보이면** 성공(지금은 다시 보임).
   - 같은 날 해야 비교가 됩니다("오늘 운행일지…"는 날짜마다 새 알림).
- 지운 날 목록은 비회원 화면에 보이는 변화가 없어 테스트로만 확인합니다.

### 확인할 점
1. 지운 날 목록은 비회원에게 보이는 효과가 없습니다(로그인 계정 서버 불러오기에만 쓰임). 로드맵 문구대로 **같이 복원**할지(권장 — 백업에 이미 들어 있고 몇 줄이면 됨), 닫은 알림만 할지 정해 주세요.
2. 복원은 "합치기"가 아니라 "백업 시점으로 교체"입니다(다른 기록과 같은 방식). 그대로 괜찮은지 확인해 주세요.
