## Capacitor 전환 C-1 — 안드로이드 앱 기본 틀 `[x]`

보리 요청: `[확인: 2026-11-05 보리 — "승인하리하고 Capacitor로 바로 진행하자 최우선이야 급해"]`. 테스터 모집 서비스가 TWA 앱은 받지 않고 네이티브 웹뷰·Capacitor는 받는다고 함. 로드맵의 "출시 후 Capacitor 전환"을 앞당긴다. sot에 앱 포장 규칙 없음(검색: TWA·Capacitor).

전체 순서(이번엔 **C-1만**):
- C-1 기본 틀: 앱이 운행일지 사이트를 주소줄 없이 연다.
- C-2 구글 로그인: 구글은 앱 안 웹뷰 로그인을 막는다. 안드로이드 방식 로그인으로 바꾼다.
- C-3 파일 저장·공유: PDF·엑셀 저장과 카카오톡 공유를 앱 방식으로.
- C-4 운비서 음성: 마이크 입력과 읽어 주기를 앱 방식으로.
- 그다음 1.0.2를 비공개 테스트 트랙에 올린다(코드 변경 없음). C-2까지 안 되면 테스터가 로그인을 못 하므로 그 전에는 올리지 않는다.

### 쉬운 요약
- 지금 앱은 크롬을 빌려 쓰는 TWA다. 이걸 앱 안에 화면을 직접 띄우는 Capacitor 앱으로 바꾸는 첫 단계다.
- 앱은 지금처럼 `getdrivelog.com`을 불러온다. 그래서 사이트를 배포하면 앱 업데이트 없이 앱 화면도 바로 바뀐다.
- 패키지 이름 `com.getdrivelog.app`과 서명 키가 같아서 플레이 스토어에서는 같은 앱의 새 버전이 된다.

### 현재 상태 (코드 확인)
- 앱 파일은 PWABuilder가 만든 TWA다. `C:\dev\drivelog-keys\v2\` 안에 `.aab`·`.apk`·`signing.keystore`·`signing-key-info.txt`가 있고, react-app 저장소에는 안드로이드 코드가 없다(`ls react-app` — `android/` 없음).
- `package.json`에 Capacitor 없음. 웹 화면 코드는 앱 여부를 따지지 않는다.
- 이 컴퓨터에 안드로이드 스튜디오(자바 21 포함 `jbr`)와 SDK(플랫폼 37, 빌드 도구 36)가 있다.
- 플레이 콘솔에 올라간 마지막 버전은 1.0.1(코드 2).

### 목표 상태 (기대 동작)
1. react-app에 Capacitor 8.6.0(`@capacitor/core`·`@capacitor/cli`·`@capacitor/android`)을 넣고 `capacitor.config.ts`를 만든다. 앱 이름 "운행일지", 패키지 `com.getdrivelog.app`, 불러올 주소 `https://getdrivelog.com`.
2. `npx cap add android`로 만든 `android/` 폴더를 저장소에 넣는다. 버전은 1.0.2(코드 3).
3. 앱 아이콘과 시작 화면을 지금 아이콘(`public/icons/icon-512.png`)·바탕 #121212로 맞춘다. `@capacitor/assets`(개발용 도구)로 만든다.
4. 휴대폰(또는 에뮬레이터)에서 앱을 열면 주소줄 없이 운행일지 화면이 뜬다. 뒤로 가기는 앞 화면으로, 첫 화면에서는 앱을 닫는다(Capacitor 기본 동작).
5. 같은 업로드 키(`v2\signing.keystore`)로 서명한 `.aab`·`.apk`를 저장소 밖 `C:\dev\drivelog-keys\v3\`에 만든다. 키 비밀번호는 저장소에 넣지 않는다(빌드 때만 입력).
6. 웹 화면 코드(`src/`)는 한 줄도 안 바뀐다. 사이트는 지금과 똑같이 동작한다.
