### 쉬운 요약
- **무엇을:** 운송료가 0원이거나 이미 다 받은 운행은 미수 목록에 넣지 않는다.
- **왜:** 지금은 0원 운행도 "미수"로 잡혀서 홈 "미수금 8건"·미수금 화면 "미수 (전체 0원)"이 나오고, 매출은 "미입금 7건"으로 건수가 다르다(금액은 같음).
- **달라지는 점:** 홈·미수금 화면·알림·매출의 미수 건수가 같아진다.

### 현재 상태 (코드 확인)
- 미수 목록의 정본 `domain/financeReceivables.js:38-90` `getReceivableItems`: "다 받음(`paid`)"만 빼고 나머지는 다 넣는다. 운송료 0원이고 입금 기록이 없으면 상태가 "안 받음(`unpaid`)", 남은 돈 0원이라 목록에 들어간다(`financeCore.js:41-48`).
- 이 목록을 쓰는 곳: 미수금 화면·홈 할 일 카드(`useReceivablesData.js:28`), 알림의 연체 미수(`lib/notifications.js:54`), 연체 목록(`getOverdueReceivableItems`, `:99`), 매출 "미입금"(`financeOwnerDetail.js:144-147`).
- 매출만 따로 `remainingAmount <= 0`을 걸러서(`financeOwnerDetail.js:145`) 건수가 1건 적다.
- 0원 운행의 "운행 횟수"는 운행이니 그대로 센다 — 이번 범위 아님.
- 테스트 영향 미리 찾음: 미수 목록을 쓰는 테스트 10개 파일(`finance.test.js`, `receivables-invoices.test.js`, `notifications*.test.js`, `NotificationsPage.test.js`, `App.test.js`, `callDetailIds.test.js`, `receivablesCloudCommit.test.js`, `ownerDataHooks.test.js`)에서 0원 운행을 미수로 기대하는 곳을 찾지 못했다(0원 운송료가 나오는 테스트는 `CalendarMonthSummary.test.js:31`·`monthSettlement.test.js:169`뿐, 둘 다 미수와 무관). 그래서 기존 기대값은 안 바뀔 것으로 본다.

### 목표 상태 (기대 동작)
1. 미수 목록은 **남은 돈이 0원보다 큰 운행만** 담는다(0원 운행, 다 받은 운행 제외). 일부만 받은 운행은 지금처럼 남은 돈으로 담는다.
2. 홈 "미수금 N건", 미수금 화면, 연체 알림, 매출 "미입금 N건"이 같은 건수·금액.
3. 매출의 따로 거르는 조건(`financeOwnerDetail.js:145`의 `remainingAmount <= 0`)은 이제 중복이지만, 이번엔 그대로 둔다(동작 같음, 범위 최소).
4. 0원 운행 저장은 **막지 않는다**(아래 질문 1 — 추천).
