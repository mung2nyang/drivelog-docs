### 쉬운 요약
- 로그인 계정 일지는 입력이 멈추고 0.6초 뒤 서버에 저장되는데, 저장이 1초쯤 걸리는 동안 또 고치면 (1) 앞 저장이 끝나는 순간 "저장할 것 없음"으로 표시가 내려가 그 직후 화면을 닫으면 마지막 수정이 저장되지 않고, (2) 두 저장이 동시에 돌아 서로 덮을 수 있다.
- 같은 날짜 저장은 한 번에 하나만 돌리고, 도는 중에 또 고치면 끝난 뒤 최신 내용으로 한 번 더 저장한다. "저장 대기" 표시는 마지막 수정까지 저장됐을 때만 내린다.
- 끝나면 빠르게 고치고 바로 나가도 마지막 내용이 서버에 남는다.

### 현재 상태 (코드 확인)
- `components/day-log/useDayDraft.js:124-134` 로그인 경로: `commitMainDayLogToCloud`를 기다리지 않고 부르고(`void … .then`), 성공하면 `markSaved`가 `hasPendingRef.current = false`(`:81`)를 판 번호(`draftRevRef`) 확인 없이 함.
- 판 번호 확인은 비회원 경로에만 있음(`dayDraftLifecycle.js:41-46` `settlePendingDayWrite`, `attemptRev !== draftRevRef.current`면 안 내림).
- 언마운트 flush는 `hasPendingRef`만 봄(`useDayDraft.js:183-187`) → 앞 저장 성공으로 false가 되면 마지막 수정 저장 건너뜀.
- 같은 날짜 저장이 겹치는 것을 막는 장치 없음(`commitNow`가 매번 새 저장 시작, `:106-137`). 서버 쪽은 지운 뒤 다시 넣기라(`dayLogCloudCommit.js:49-71`) 겹치면 지운 콜이 남거나 늦게 끝난 옛 저장이 Store를 덮을 수 있음.
- 같은 방식("저장 중이면 끝난 뒤 최신 값으로 한 번 더")이 개인정보 화면에 이미 있음(`components/usePersonalInfoDraft.js:25-48` `savingRef`, 테스트 `PersonalInfoPage.typing.test.js`).

### 목표 상태 (기대 동작)
1. 로그인 경로에서 같은 일지 화면의 서버 저장은 한 번에 하나만 돈다.
2. 저장 중에 또 고치거나(디바운스 끝) 화면을 닫으면(언마운트 flush) 새 저장을 바로 시작하지 않고, 지금 저장이 끝난 뒤 **최신 draft로 한 번** 저장한다(여러 번 고쳐도 한 번).
3. 저장 성공 시 그 저장이 시작될 때의 판 번호가 지금 판 번호와 같을 때만 "저장 대기"를 내리고 "저장됨"으로 표시한다. 다르면 대기 상태 유지(다음 저장이 처리).
4. 앞 저장이 실패해도 그 뒤에 고친 내용이 있으면 이어서 최신 내용으로 저장을 시도한다. 실패 안내·"저장 실패" 표시·나가기 전 확인(35번)은 지금과 같다.
5. 비회원·서버에 없는 차량(로컬 경로)은 동작 변화 없음.

### 검증
- 자동: `npm test`·`typecheck`·`build`(CI 재실행), 엄격 검사 경고 수 457 이하.
- 새 테스트(가짜 서버로 저장을 붙잡아 두고):
  - S-1 저장 중 수정 → 첫 저장이 끝날 때까지 두 번째 서버 저장 0회 → 끝난 뒤 최신 내용으로 1회.
  - S-2 저장 중 수정 → 첫 저장 성공 → 바로 화면 닫기 → 마지막 수정이 서버로 저장됨(지금 코드면 실패해야 함).
  - S-3 저장 중 여러 번 수정 → 끝난 뒤 저장 1회만, 내용은 마지막 것.
  - S-4 첫 저장 실패 + 그 뒤 수정 → 최신 내용으로 이어서 저장, 실패 안내 1회.
  - 기존 일지 테스트(35·36번, StrictMode, App 일지 테스트) 그대로 통과.
  - 진실성: 고치기 전 코드로 되돌려 S-1·S-2가 실패하는 것 확인(플레이북 §6).
- 브라우저: 개발 서버 시험 계정. 인터넷 속도를 늦춰(개발 도구 "느린 4G") 저장 겹침을 만들어 확인.

### 사용자 확인 방법
1. 차주 시험 계정 → 오늘 일지 → 운행 하나 추가(운송료 10,000원) 후 바로 메모(비고)를 고침.
2. 제목 옆 표시가 "저장 중…" → "저장됨"으로 바뀌기 전에 ← 로 나감.
3. 다시 그 날짜 일지를 열거나 새로고침 → 고친 메모까지 남아 있으면 성공.
