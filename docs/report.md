1. **저장 방식** (J-2)
   - **권함 가**: 카드에 "오늘 일상점검표를 모두 양호로 저장할게요."와 [저장하기] 버튼을 보인다. 누르면 그 자리에서 저장한다(일지 점검표 창의 저장과 같은 함수, 점검자 이름도 같음).

3. **차량** (J-2)
   - **권함 가**: 메인 차량 일지의 점검표에만 쓴다. 연동 기사는 자기가 모는 차량이다. 일지 안내 줄이 쓰는 차량과 같다(`DailyInspectionNotice` `logId` 'main').

### 쉬운 요약
- "오늘 점검표 모두 양호", "어제 일상점검 다 양호야"를 운비서가 점검표 처리 말로 알아듣고 날짜를 붙여 돌려준다.

### 현재 상태 (코드 확인)
- `unbiseo-parse`의 종류 목록에 점검표가 없다(`grok.ts` 85줄 `enum: ['call', 'expense', 'question', 'fixed', 'client', 'sms', 'weather', 'unknown']`). 그래서 점검표 말은 unknown이나 다른 종류로 간다.
- 날짜 칸(`date`)은 이미 있다. 운행·지출·고정이 같이 쓰고, 앞날은 `dayOf`(`index.ts` 74줄)가 오늘로 바꾼다.
- "문자"가 없는 말은 서버 코드가 unknown으로 막는 선례가 있다(`index.ts` 121줄).
- 점검표는 11항목이고 양호·불량 중 하나다(`domain/dailyInspectionItems.ts`). 일지 창의 [모두 양호]는 `allGoodItems()`, 저장은 `saveDailyInspection`(차량+날짜로 덮어씀)이다.

### 목표 상태 (기대 동작)
1. 새 종류 `kind: 'inspection'`, 답은 `{ kind: 'inspection', inspection: { date } }`이다.
   - `date`는 기존 `date` 칸을 쓴다(확인할 점 2). 새 칸은 없다.
2. 점검표·일상점검을 "모두·다·전부 양호(이상 없음)"로 처리하라는 말만 inspection이다. 일부 항목이나 불량을 말하면 unknown이다("브레이크 불량" 등).
3. **말에 "점검"이 없으면** AI가 inspection이라 해도 서버 코드가 unknown으로 바꾼다("문자" 막기와 같은 방식).
4. 다른 종류는 지금과 같다(기존 시험 문장 전부).
5. 저장은 하지 않는다. 함수 기록은 지금처럼 끝난 이유·시간만 남긴다.
