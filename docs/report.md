## Capacitor 전환 C-4 — 앱 안 운비서 음성(말하기·읽어 주기) `[x]`

2026-11-06 보리 요청("그다음에 c-4운비서로"). 승인 `[확인: 2026-11-06 보리 — "1번으로 착수지시서 확정, 작업 진행해"]`. 근거: 로드맵 "Capacitor 전환" C-4, sot "운비서" 줄(마이크 받아쓰기 24-B-1, 읽어 주기 24-E, xAI 목소리 24-E2). 앞 조각 C-3(파일 저장·공유)과 같은 방식으로 앱일 때만 바꾸고 웹은 그대로.

### 쉬운 요약
- 앱에서 운비서 마이크를 눌러 말하면 휴대폰의 안드로이드 받아쓰기로 알아듣고, 답을 소리로 읽어 주게 합니다.
- 지금 앱은 크롬 받아쓰기 기능을 쓰는데, 앱 안 화면(웹뷰)에는 그 기능이 없고 앱에 마이크 권한도 없어서 말이 들어가지 않습니다.
- 웹(크롬)은 지금 그대로입니다.

### 현재 상태 (코드 확인)
- 받아쓰기: `useSpeechInput.ts`가 `window.SpeechRecognition`/`webkitSpeechRecognition`(크롬 받아쓰기)만 씀. 앱 설정 파일(`AndroidManifest.xml`)에 마이크 권한(`RECORD_AUDIO`)이 없음(권한 줄은 인터넷·옛 저장소 2개뿐). 안드로이드 웹뷰는 크롬과 달리 받아쓰기 기능을 갖고 있지 않음.
- 마이크 버튼: 2026-11-06 에뮬레이터에 v4 앱을 깔아 보니 홈 운비서 줄에 마이크 버튼은 보임(웹뷰가 받아쓰기 이름은 갖고 있어 `supported`가 참). 실제로 눌러 듣는지는 로그인 계정만 되어(`HomeAssistantBar.jsx` `if (!assistant.loggedIn) return`) 에뮬레이터에서 못 봄.
- 읽어 주기: `useSpeechOutput.ts`가 xAI 목소리(서버 함수 `unbiseo-voice`, `<audio>`로 틂)를 먼저, 못 받으면 `window.speechSynthesis`(휴대폰 기본 목소리). 앱 웹뷰는 소리 자동 재생을 막지 않게 되어 있음(Capacitor `Bridge.java` `setMediaPlaybackRequiresUserGesture(false)`) → xAI 목소리는 그대로 날 것으로 봄. 대신 쓰는 휴대폰 기본 목소리는 웹뷰에서 동작이 보장되지 않음.
- 읽어 주기는 마이크로 말한 답만 함(sot 24-E) → 받아쓰기가 안 되는 지금 앱에서는 읽어 주기도 한 번도 안 일어남.

### 목표 상태 (기대 동작)
1. 앱에서 운비서 마이크를 처음 누르면 안드로이드 마이크 권한 창이 뜬다. 허용하면 바로 듣는다.
2. 말이 끝나면 받아쓴 글자로 지금처럼 바로 보낸다(웹과 같은 흐름 — 듣는 중 표시, 다시 누르면 멈춤).
3. 권한을 거절하면 지금 웹과 같은 안내 "마이크 사용을 허용해 주세요. 음성 대신 직접 입력해도 됩니다.", 아무 말도 못 알아들으면 "음성을 인식하지 못했어요. 다시 눌러 말씀해 주세요.", 그 밖의 실패는 "음성을 글자로 바꾸지 못했어요. 직접 입력해 주세요."(문구 새로 안 만듦).
4. 앱에서 말로 보낸 답은 xAI 목소리로 읽고, 못 받으면 안드로이드 기본 목소리(한국어)로 읽는다. 하루 횟수를 다 쓰면 지금처럼 소리 없이 안내 문구만.
5. 듣기 시작·새로 보내기·계정 바뀜이면 읽던 것을 멈춘다(안드로이드 기본 목소리도).
6. 웹(크롬)은 받아쓰기·읽어 주기 모두 지금과 같다.
