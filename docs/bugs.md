## 보리 제보

- **연동을 해제했는데 "연동을 먼저 해제해야 탈퇴할 수 있습니다."로 탈퇴가 막힘** `[확인: 2026-11-07 보리]` — 화면엔 연동 중이 아닌데 탈퇴 불가.
  새 계정 테마 확인(탈퇴 뒤 다시 가입)도 이것 때문에 못 함. 막는 곳이 두 군데:
  앱 화면(`features/account/ui/PersonalInfoPage.jsx:47-51` — 계정 종류가 `employed_driver`이거나 기사 목록에 `linked`가 있으면)과
  서버(`supabase/migrations/0009_block_withdraw_while_linked.sql` — `driver_links`에 `status = 'linked'` 줄이 있으면, 해제 요청 중도 linked).
  보리 답(2026-11-07): 기사 계정, [탈퇴]를 누르자마자 토스트, 해제는 1~2일 전(차주 동의), 마이페이지·개인정보엔 연동 중 표시 없음 → 앱 화면 쪽 판정.
  **원인 확인(2026-11-07, Supabase·앱 화면): 버그 아님, 정한 대로 막은 것.** 이 계정("테스트2")은 기사로서의 연동은 해제됐지만
  (`driver_links` 두 줄 모두 `disconnected`), 같은 계정이 차주로서 "테스트기사"를 2026-10-22부터 연동 중(`linked`, 차량 00가0000)이다.
  마이페이지 "기사 연동 관리"에 연동 중 1명으로 보임. 탈퇴하려면 그 연동을 먼저 해제해야 함(앱 `PersonalInfoPage.jsx:49`, 서버 0009 모두 같은 판정).
  남는 불편: 토스트가 어느 연동인지 말하지 않아 기사 쪽만 확인하게 됨 — 고칠지 보리 결정 전.
  (이 계정이 차주이자 기사가 된 경위는 바로 아래 항목.)
- **한 계정이 차주이면서 동시에 연동 기사가 될 수 있는데, 화면은 한쪽만 보임** `[확인: 2026-11-07 보리]` — 실제 사례: "테스트2"가 차주로서
  "테스트기사"와 연동 중(10-22~)인 채로 11-03에 "테스트" 차주의 기사로 연동됨(11-06 해제). 기사로 연동돼 있는 동안 앱은 차주의 장부로
  바뀌어(`data/cloud/appSession.ts` `ownerKeyFromSession`) 자기 차량·자기 기사 연동이 전혀 안 보이고, 마이페이지에도 "연동중"만 보임.
  서버 초대 코드 함수는 "이미 기사로 연동됨"만 막고, 자기가 차주로 기사를 둔 경우는 막지 않음(`0019_driver_invite_code_hardening.sql:75`).
  sot에 정한 규칙 없음. **정함 `[확인: 2026-11-07 보리 — "1번으로 하자"]`: 막는다** — 차주로서 연동 중인 기사가 있으면 초대 코드 입력을
  서버에서 거절하고 "연동 중인 기사를 먼저 해제해 주세요" 같은 안내. 바로 위 탈퇴 토스트 문구 개선과 묶을 수 있음. 언제 할지는 아직 안 정함.

## 옛 로드맵 "후속 nit"에서 옮긴 것

지금 동작 오류는 없거나 급하지 않아 남겨 둔 것. 그 뒤 고쳐졌을 수 있으니 손대기 전에 남았는지부터 확인한다.

- **문의 관리자·알림 뒤에 남은 작은 것 4개** `[확인: 2026-10-22 보리]` — 지금 동작 오류 없음.
  - 화면을 옮길 때마다 문의 알림을 서버에 다시 물음(`useInquiryNotices.ts`). 관리자는 이때 모든 문의 내용까지 받아 건수만 셈
    (`inquiryNotices.ts` `fetchPendingInquirySummary`) — 문의가 많아지면 무거워짐.
  - 관리자인지 확인(`useIsAdmin`)이 쓰는 곳마다 따로 서버에 감. 알림 화면을 열면 여러 번.
  - 고객센터 `?tab=my` → `initialTab` 연결(`AppShellRoutes.jsx`)은 테스트 없이 브라우저로만 확인함.
  - 사용자 "나의 문의" 카드(`MyInquiriesList.jsx`)엔 답변 시각이 안 나옴(관리자 카드엔 나옴).
- **`html2pdf.js` 새 버전 나오면 올리기** `[확인: 2026-10-10 보리]` — 지금 0.14.0이 옛 DOMPurify 3.3.1을 자기 파일에 묶어 옴.
  위험 기능 안 쓰고 입력은 우리 보고서 화면뿐이라 지금은 공격 길 없음. 새 버전이 나오면 올리고 PDF 저장 확인.
- **"결제 및 수금 입력"이 꺼진 1인 차주는 그 칸을 못 봄** — 산재·원천징수 재설계 슬라이스 3(2026-09-27) 때 범위 밖으로 남김(`docs/sot.md` §4-12).
- **빈 날 삭제 표시(`workDataDeletedDates`)가 서버 원본을 못 지우는 좁은 경우** `[확인: 2026-09-14]` — 동기화 안 된 차량의 빈 날 삭제.

- **`mergeDriversFromRows` 이름·전화번호 버그 수정에 전용 회귀 테스트 없음** `[확인: 2026-09-17]` — 필요하면 따로 요청.
