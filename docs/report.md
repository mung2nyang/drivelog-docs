## 11-D-1 스토어 등록 글 자료 초안 `[x]`

보리 요청(2026-11-03, 11-B 승인 뒤 다음 순서). 근거: 로드맵 11번 "스토어 등록 자료 — 설명 문구·데이터 보안 항목·스크린샷·대표 이미지 초안(AI 작성, 문서만), 심사용 테스트 계정". 11-D를 셋으로 나눠 **이번엔 11-D-1(글)만**:
- **11-D-1 글 자료** — 플레이 콘솔에 그대로 붙여 넣을 문구와 설문 답안.
- 11-D-2 그림 자료 — 대표 이미지 1024×500, 휴대폰 스크린샷 2~8장(개인정보 없는 화면으로).
- 11-D-3 심사용 접근 안내 — 비회원으로 시작하기로 충분한지, 로그인 기능 심사용 구글 계정이 필요한지.

### 쉬운 요약
- 플레이 콘솔은 앱 설명, 분류, 연락처, "데이터 보안" 설문, 콘텐츠 등급 설문, 대상 연령 같은 글을 요구한다.
- 이걸 처리방침·약관·실제 기능과 어긋나지 않게 한 문서에 미리 써 둔다. 신원 확인이 끝나면 보리가 칸마다 붙여 넣기만 하면 된다.
- 앱 코드와 화면은 바뀌지 않는다.

### 현재 상태 (코드 확인)
- 스토어용 글 문서 없음(`docs/`에 해당 파일 없음).
- 근거가 될 공개 문서는 있음: `react-app/public/privacy.html`(2항 수집 항목 표, 6항 위탁·국외 이전 — Supabase·xAI·기상청), `terms.html`(만 14세 미만 가입 제한), `account-deletion.html`(11-A).
- 비회원 시작 단추 있음(`AuthIntroView.jsx` 55줄 "비회원으로 시작하기") — 심사자가 로그인 없이 볼 수 있는 길(11-D-3에서 정함).
- 광고 없음, 결제 없음(11-C에서 Google Play billing 끔).

### 목표 상태 (기대 동작)
1. 새 문서 `docs/play-store-listing.md`에 아래가 칸 이름 그대로 정리돼 있다.
   - 기본 정보: 앱 이름(30자 안), 짧은 설명(80자 안), 자세한 설명(4000자 안), 앱/게임 구분, 분류(카테고리) 추천과 이유, 연락처 이메일·웹사이트·처리방침 주소
   - 데이터 보안 설문 답안: 수집·공유 여부, 항목별(이름·이메일·전화번호·계좌 등 금융 정보·대략적 위치·앱 활동·오류 기록 등) 수집 목적·필수/선택·일시 처리 여부, 전송 암호화, 삭제 요청 방법(11-A 주소) — 각 답 옆에 처리방침 몇 항이 근거인지
   - 콘텐츠 등급 설문 답안(폭력·성적 내용·도박·사용자 간 소통 등), 대상 연령(만 18세 이상 업무용 권장 이유), 광고 없음, 앱 접근 권한 안내 초안(11-D-3에서 확정)
2. 글자 수 제한을 넘는 칸이 없다(문서에 칸마다 글자 수를 적는다).
3. 처리방침과 다른 내용이 없다. 처리방침에 없는 수집이 필요해 보이면 문서에 쓰지 않고 따로 질문으로 올린다.
4. 보리가 정해야 하는 것(분류, 대상 연령 등)은 문서 끝 "보리 확인할 것"에 모은다.
