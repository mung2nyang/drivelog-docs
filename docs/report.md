코드 리뷰(2026-10-14)로 로드맵 72번 등재 `[확인: 2026-10-14 보리]`, 순서 ①(데이터 저장·유실). 71번 다음. 플레이북 트리거 해당(`localStorage` 쓰기·저장 경로) — `docs/testing-playbook.md` 열람함. DB 변경 없음.
`docs/sot.md` 확인: 나가기 전 확인·일지 자동 저장 시점에 대해 정한 규칙은 없습니다(`grep "beforeunload\|나가기 전\|디바운스" docs/sot.md` 0건).

### 쉬운 요약
- **무엇을:** 일지를 고친 직후(자동 저장 0.6초 대기 중)나 서버에 저장하는 중에 새로고침·앱 닫기·당겨서 새로고침·로그아웃을 해도 마지막 입력이 사라지지 않게 합니다.
- **왜:** 지금은 "나가기 전 확인"이 **저장에 실패한 기록**만 봅니다. 그래서 저장을 기다리거나 저장하는 중이면 확인 없이 새로고침되어 마지막 입력이 사라집니다. 앱을 내렸을 때(화면 숨김)도 일지를 바로 저장하지 않아, 그 사이 휴대폰이 앱을 끄면 사라집니다.
- **달라지는 것:**
  - 앱을 내리거나 닫는 순간, 기다리던 저장을 바로 시작합니다. 비회원은 기기에 바로 저장돼서 끝납니다.
  - 로그인 계정이 서버 저장을 마치기 전에 새로고침·로그아웃하려 하면 확인 창을 띄웁니다.
  - 앱 안에서 화면을 옮기는 것은 지금처럼 확인 없이 됩니다. 화면이 닫히면 저장을 마저 하는 장치가 이미 있습니다(`useDayDraft.js:192-196`).

### 현재 상태 (코드 확인)
- 자동 저장: 입력 뒤 0.6초 기다렸다가 저장합니다(`components/day-log/useDayDraft.js:22·164`).
  - 비회원·서브 차량은 기기에 바로 씁니다(`:92-106`, 동기).
  - 로그인 메인 일지는 서버에 쓰고, 성공해야 화면 저장으로 확정됩니다(`:126-143`, 비동기, 한 번에 하나 — 65번).
- 나가기 전 확인 `lib/durableWriteGuard.js:59-76` — 판단은 `isDurableWriteBroken()` = 기기 저장 대기 큐 실패 또는 저장 실패 표시(35번 `markUnsafeRegistrationFailure`)뿐입니다. "기다리는 중·저장 중"은 보지 않습니다.
  - 쓰는 곳: 브라우저 닫기·새로고침(`app/pendingWriteRetryListeners.js:58` `beforeunload`), 당겨서 새로고침(`app/usePullToRefresh.js:88`), 로그아웃(`app/useAppSession.js:119`), 앱 안 이동(`AppShell.jsx:65`, `MainPageRoute.jsx:102`, `DayLogPage.jsx:94`).
- 화면 숨김·닫힘(`visibilitychange`·`pagehide`) 때는 안 쓰는 outbox만 비우고 일지는 저장하지 않습니다(`app/syncFlushListeners.js:11-25`).
- `useDayDraft.js`는 199줄입니다. 줄을 더하면 200줄을 넘습니다(AGENTS §6).

### 정해 주실 것 (AGENTS §7 — 새 장치)
"기다리는 중·저장 중인 일지"를 화면 밖(새로고침 확인)에서도 알 수 있게, **기기에 저장하지 않는 메모리 안의 작은 목록**이 하나 필요합니다(`lib/dayDraftActivity.js`). 열린 일지마다 "저장할 게 남았나"와 "지금 바로 저장하기" 함수를 올려 두고, 저장이 끝나거나 화면이 닫히면 내립니다.
- 새 저장 키·재시도 큐·임시 보관은 아닙니다. 앱을 끄면 같이 사라집니다.
- 이것 없이 하는 방법은, 확인 창 없이 숨김·닫힘 때 바로 저장만 시작하는 것(아래 목표 1·2만)입니다. 다만 로그인 계정의 새로고침 중 유실(목표 3·4)은 막지 못합니다.
- **추천: 목록을 만듭니다.** → 보리 결정(2026-10-14): 추천대로.

### 목표 상태 (기대 동작, 위 추천 기준)
1. 일지를 고친 뒤 0.6초 안에 앱을 내리거나(화면 숨김) 닫으면(`pagehide`), 기다리지 않고 바로 저장을 시작합니다. 비회원·서브 차량은 그 자리에서 기기에 저장됩니다.
2. 비회원이 고친 직후 새로고침하면 확인 창 없이 저장한 뒤 새로고침됩니다. 새로고침 뒤 마지막 입력이 그대로 있습니다.
3. 로그인 계정이 서버 저장 중(또는 대기 중)에 브라우저 새로고침·닫기를 하면 브라우저 기본 확인 창이 뜹니다. 저장은 이미 시작된 상태입니다.
4. 로그인 계정이 저장 중에 당겨서 새로고침·로그아웃을 하면 "방금 고친 내용을 아직 저장하는 중입니다. 그래도 나가시겠습니까?"가 뜹니다. 취소하면 그대로 남고, 저장은 계속됩니다.
5. 저장이 끝나면(성공) 목록에서 빠져 확인 창이 다시 뜨지 않습니다. 실패하면 지금처럼 35번 실패 표시가 맡습니다(문구 그대로).
6. 앱 안 화면 이동(일지 닫기·하단 탭 등)은 지금과 같습니다. 저장 중이라는 이유만으로 확인 창을 띄우지 않습니다.
