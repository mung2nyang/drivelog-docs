코드 리뷰(2026-10-14)로 로드맵 70번 등재 `[확인: 2026-10-14 보리]`, 순서 ①(데이터 저장·유실). 69번 다음. 플레이북 트리거 해당(저장·동기화 경로) — `docs/testing-playbook.md` 열람함. DB 변경 없음.

### 쉬운 요약
- **무엇을:** 로그인 차주가 정비·주유·기타 지출을 저장할 때, 메인 차량과 미연동 기사 차량도 연동 차량처럼 **바뀐 항목만** 서버에 쓰게 합니다.
- **왜:** 지금은 지출 1건만 고쳐도 그 차량의 **운행한 모든 날짜** 지출을 지우고 다시 씁니다. 1년(운행 300일)이면 저장 한 번에 서버 요청이 약 1,800번(지우기·넣기 × 날짜 × 3종류)이라 매우 느립니다. 중간에 끊기면 일부 날짜 지출이 서버에서 지워진 채 남습니다.
- **달라지는 것:** 저장 한 번에 요청이 몇 번으로 줄고, 끊겨도 다른 날짜 지출은 건드리지 않아 사라지지 않습니다. 화면과 금액은 그대로입니다.

### 현재 상태 (코드 확인)
- `lib/expenses.js:42-62` `saveExpenses`(로그인 차주) — 차량별로 나눈 뒤(`planExpenseVehicleTargets`), 연동 기사 차량(`mode: 'items'`)만 `syncExpenseItemsForVehicle`로 항목 단위 저장을 합니다. 메인·미연동 기사 차량(`mode: 'dates'`)은 `syncFuel/Maintenance/MiscExpenseRecords`(`lib/syncExpenseRecords.js:42-134`)로 저장합니다.
- 날짜별 다시 쓰기(`syncExpenseRecords.js:49-67`): 순회 날짜 = 그 차량 **운행 기록 전체 날짜** + 지출 날짜 + 정리 날짜(`:19-21`). 날짜마다 `delete` 1번 + `insert` 1번이고, 표 3개라 ×3입니다. 그래서 지출이 없는 운행 날짜도 `delete`를 보냅니다.
- 항목 단위(`lib/syncExpenseItems.js:94-140`): 서버 줄을 한 번에 읽고(1,000줄 넘어도 끝까지, 67-B), 항목 번호로 비교합니다. 새 항목은 넣기, 바뀐 항목은 고치기, 내가 알던 것 중 없어진 것만 지우기를 하고, 안 바뀐 항목은 요청 0번입니다.
- 옛 방식이 대신 해 주던 일 두 가지:
  - ⓐ **다른 차량으로 옮긴 지출**은 옛 차량의 그 날짜를 다시 써서 지웠습니다(`cleanupDates`, `domain/expenseVehicleRouting.js:48·71·76`, `expenses.js:55-58`).
  - ⓑ **서버에 없는데 화면엔 있는 지출**(앞선 저장이 끊긴 경우)은 다시 써서 되살렸습니다. 항목 단위는 연동 칸에서 "상대가 지운 것"이라 되살리지 않습니다(`syncExpenseItems.js:116-117`).

### 목표 상태 (기대 동작)
1. 로그인 차주의 메인·미연동 기사 차량 지출도 항목 단위로 저장합니다. 안 바뀐 항목은 서버 요청 0번이고, 지출이 없는 운행 날짜에 지우기 요청을 보내지 않습니다.
2. 항목을 고치면 고치기 1번, 새로 넣으면 넣기 1번, 지우면 그 항목 지우기 1번입니다.
3. 지출을 다른 차량으로 옮기면(ⓐ) 새 차량엔 넣고, 옛 차량 서버 줄은 지웁니다. 방법: 차량마다 "내가 알던 항목"에 저장 전 그 차량 항목과 **이번에 다른 차량으로 간 항목**을 같이 넘깁니다. 연동 차량이 메인 칸에서 옛 항목을 옮겨 갈 때도 같은 규칙으로 메인 칸의 옛 줄이 지워집니다.
4. 차주만 쓰는 칸(메인·미연동)은 안 바뀐 항목이 서버에 없으면 다시 넣습니다(ⓑ 유지). 연동 칸은 지금처럼 되살리지 않습니다. (보리 결정 2026-10-14: 추천대로)
5. 중간에 끊기면 지금처럼 안내가 뜨고 화면은 저장 전 그대로입니다. 다음 저장 때 이미 들어간 항목은 고치기로 처리돼 두 번 들어가지 않습니다(항목 번호 기준).
6. 연동 기사 본인 저장(`expenses.js:32-41`)과 연동 차량 칸 동작은 바뀌지 않습니다.
